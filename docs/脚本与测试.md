# 脚本与测试

> **状态：现行** ｜ `scripts/` 下的工具分两类：**验证类**（可反复跑、多数只读）与**运维类**（会动文件）。
> 加脚本的原则：一次性诊断做完就移入 `scripts/_legacy/`，别让 `scripts/` 变成杂物间。

---

## 一、验证类（日常都该跑）

| 脚本 | 作用 | 会写什么 |
|---|---|---|
| **`selftest.py`** | 核心逻辑回归（约 2,400 行，覆盖判定/分档/批次/分页/空间统计/任务状态机/快捷键文案一致性/配置容错） | 只在 `tempfile` 里造库造文件 |
| **`smoke_ui.py`** | **真渲染冒烟**：Streamlit 官方 `AppTest` 把整页跑一遍 | 只点「跳到分数 ≥」一个按钮（纯 COUNT + 队列定位） |
| `smoke_audio.py` | 引擎冒烟：真实中文语音 vs 纯噪声，验证 VAD+ASR 行为 | 无（需先装引擎与模型，首次载入模型 1–3 分钟） |

### `selftest.py` 里最值钱的几条断言（别删）

- **代码审计：`src/` 下不得出现任何删除调用** —— 这是"程序永不删除"这条红线的**机器保证**，
  不是承诺。清自创临时目录的行尾必须带 `# AUDIT-OK` 注释。
- **`test_hl_version_single_source`**：`config.json` / `highlighter.HL_VERSION` /
  `db.HIGHLIGHT_TARGET_VERSION` 三处版本号必须相等（漂移是单向且不可见的，见 [`数据模型.md`](数据模型.md) 第六节）。
- **口径一致性**：计数方法与队列方法同口径；`no_clip_breakdown()` 四个分义之和 == 无精华总数且互斥。
- **快捷键键位 × UI 按钮文案一致**：`hotkeys` 按按钮文案定位，改文案不改键位表 ⇒ 快捷键静默失效。
- **行内判据 vs 队列口径不变量**：`mover.is_pending()` 的行内实现与 `db.pending_highlight_ids()` 必须给出同一答案。
- **回归项 `test_coarse_zero_hits_no_crash`**：`cut_one` 里 `scanned` 未初始化曾让 **1,382 条**视频
  从两条剪辑队列同时消失（`highlight_error` 一旦置上，两队列都要求它为 NULL）。

### 怎么判"通过"（踩过的坑）

```bash
./.venv/Scripts/python.exe scripts/selftest.py
```

- **看 `[OK]` 计数，不要 `grep FAIL`** —— 语法错时输出里根本没有 `FAIL`，`grep` 会**假通过**。
  正确做法：先确认能 import，再数 `[OK]`。
- 脚本无 `argparse`，直接跑即可。

```bash
./.venv/Scripts/python.exe scripts/smoke_ui.py     # 改完 UI 必跑
```

> **为什么必须有 `smoke_ui`**：源码级字符串断言只能证明"函数被调用了"，证明不了"页面能渲染出来"。
> 重复 widget key、未定义变量、`StreamlitAPIException` 这类问题只在真渲染时暴露
> —— 审核台的跳转回调曾把形参 `filt` 写成 `fil`，一按就 `NameError`，源码断言查不出这种"只在回调里才执行"的错误。

## 二、运维类（动文件，先看安全边界）

| 脚本 | 作用 | 安全边界 |
|---|---|---|
| **`align_subdirs.py`** | 存量对齐：把回收目录里的原片按**保全状态**归入 `已剪辑` / `待保全` | **默认 dry-run**（只打印计划），`--apply` 才搬；只 move 不删；同盘搬迁=改目录项；**幂等**；先拿行内判断与队列口径对一遍，不一致就跳过并报出 |
| `audit_requirements.py` | 四条诉求对现库实数（需求覆盖的可复现入口） | **只读**（`mode=ro`），不写库、不移动/删除 |
| `audit_highlight.py` | 产物体检：按（症状 × 版本）分桶，单独标出"版本已是目标值却产物为空"的可疑行 | **只读**；`--recut N` 只把产物切到临时目录，不写库、不碰回收目录 |
| `compare_models.py` | 模型对照：同批**已标注**的产物比"换模型 / 换输入尺寸"有没有用 | **只读**，不写库、不动产物 |
| `compile_period.py` | 周期合辑（原型）：按周/按月把精华片段拼成一条成片 | 只读源片与库；只写 `--out` 下自创文件；输出目录为盘根时拒绝；中间片段默认保留（`--cleanup` 才清） |

### 常用命令

```bash
# 现状对齐（先干跑看计划，再真搬）
./.venv/Scripts/python.exe scripts/align_subdirs.py
./.venv/Scripts/python.exe scripts/align_subdirs.py --apply

# 只读体检
./.venv/Scripts/python.exe scripts/audit_requirements.py          # 四条诉求对现实
./.venv/Scripts/python.exe scripts/audit_requirements.py --fs     # 顺带统计目录占用（慢）
./.venv/Scripts/python.exe scripts/audit_highlight.py             # 产物体检
./.venv/Scripts/python.exe scripts/audit_highlight.py --recut 24  # 抽样重跑估救回率

# 周期合辑
./.venv/Scripts/python.exe scripts/compile_period.py --by month --list
./.venv/Scripts/python.exe scripts/compile_period.py --by month --value 2015-12
```

> ⚠️ `audit_highlight.py --recut` 与任何会跑 `cut_one` 的批量脚本，建议用
> **`./.venv/Scripts/python.exe -E`** 起（`-E` 忽略 `PYTHON*` 环境变量，绕开沙箱注入的删除守卫；
> 实测 `-E` 下 `numpy` / `cv2` 照常可用）。工作台从 `.bat` 双击启动，环境本来干净。

## 三、安装 / 依赖类

| 脚本 | 作用 | 备注 |
|---|---|---|
| `download_model.py` | 下载 YOLO 的 ONNX 并用 OpenCV DNN **逐输入尺寸**校验 | **两道门**：① 装载门（官方 `yolo11s.onnx` 在 OpenCV 5.0.0 上装载即失败）② 尺寸门（官方 `yolov8s.onnx` 把 reshape 写死 640，喂 `fine_size`(1280) 会崩在 `reshape2_layer`）。源码只在 v8.4.0 及之后提供 `.onnx` |
| `download_audio_models.py` | 下 FunASR 模型（`fsmn-vad` / `paraformer-zh` / `ct-punc`，约 1.2 GB，ModelScope 国内源） | `--skip-punc` 可跳过标点模型 |
| `setup_audio_engine.py` | 装 L2.5 引擎依赖 | **坑**：`funasr 1.4.x` 硬 pin `numpy<2`，而 Python 3.13 没有 numpy 1.26 的 wheel ⇒ 直接 `pip install funasr` 会去源码编译 numpy 而失败。脚本用 `--no-deps` 装 funasr，再手动补齐运行依赖 |

> 视觉链路**刻意不引 torch / ultralytics**（YOLO 走 OpenCV DNN + ONNX，模型仅 ~12 MB）；
> 只有音频复核（L2.5）引 torch + funasr —— **别全局升级 torch**。

## 四、`scripts/_legacy/` —— 已完成使命的一次性脚本（不维护）

| 脚本 | 当年解决的问题 |
|---|---|
| `backfill_sent.py` | 把产物 manifest 里的「粗扫送检帧数 / 命中数」回填进库（Track 0 的尺子对历史行本来是空的） |
| `diag_audio.py` | 诊断"明明有声音却判 0% 人声"卡在哪一环（抽 wav → 音量 → VAD 原始分段 → 整段转写，各步独立打印） |
| `diag_highlight.py` | 看单个视频在两级检测里到底发生了什么（每级抽帧数 / 送检数 / 每帧检出 / 动静比） |
| `make_samples.py` | 造测试样本视频（静态空场景 / 强运动），用于跑通全链路 |
| `pilot_salvage_ab.py` | 实机 A/B 试点：同一条视频只切 `keep_coarse_suspect`，对比产物（证明"降级保留"不是纸面推论） |
| `probe_blindspot.py` | 盲区补检对照：挑出被帧差预筛整段跳过的片段，按指定 fps/分辨率**真送检一遍**看捞回多少 |
| `probe_crop.py` | 配套目视核验：把补检检出的人画框放大存图，判断是真漏检还是误报 |
| `sample_highlight.py` | 30 样本验证：命中率 / 耗时 / 两级检测值不值 |

> `_legacy/` 里的脚本**不要**当作生产入口；它们读的列与产物格式可能已随口径变化。
> 其中独有的历史实测数据在 `docs/_archive/` 的对应文档里。

## 五、测试策略与提交前检查清单

**三层测试，各管一件事**：

| 层 | 证明什么 | 何时跑 |
|---|---|---|
| `selftest`（源码级 + 行为级） | 逻辑正确、口径一致、红线未被破坏 | **每次改 `src/` 都跑** |
| `smoke_ui`（真渲染） | 页面能渲染出来、回调不炸 | 改 UI 后必跑 |
| `smoke_audio`（真模型） | 引擎在真音频上的行为 | 动音频链路后跑 |

**提交前清单**（这套流程有来历：曾有一条提交删掉了 `src/` 13 个 py 文件）：

1. `git ls-files | wc -l` 与磁盘对得上吗？本该入库的源码有没有显示 `??`？
   —— 对不上说明**工作树已脱离跟踪**，先 `git log --stat` 找断裂点，**不要**闷头 `git add -A`。
2. `git add -A --dry-run` 逐条过一遍：`data/`、`.venv/`、`config.json` 该被 `.gitignore` 挡住。
3. `git diff --stat` 里有没有"大量 `---`"？内容改动小的文件会被识别成重命名，不是删除。
4. `selftest` 全绿（数 `[OK]`，别 `grep FAIL`）。
5. 改了 `src/` ⇒ **重启工作台**再跑批量操作（Streamlit 模块缓存跨 rerun 保留，
   `src.*` 一旦导入就锁在内存；`JobManager` 是同进程线程，用的也是旧代码）。

**本机环境约定**

- Python 一律 `./.venv/Scripts/python.exe`（托管版无 numpy/funasr，Anaconda 也不要）
- Streamlit 锁 `>=1.37,<2.0`（下限因 `st.fragment(run_every=)`，上限因 2.0 移除 `use_container_width`）
- 测 `.bat`：`MSYS_NO_PATHCONV=1 cmd "/c" "脚本.bat" > out.log 2>&1`，再按 **GBK** 解码读日志
