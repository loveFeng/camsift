# 启动与使用指南

面向从零开始。看完这份文档，你应该能独立完成：启动 → 配置 → 扫描分析 → 审核 → 移动 → 手动删除。

---

## 一、环境要求

| 项目 | 要求 | 怎么确认 |
|------|------|---------|
| 操作系统 | Windows 10 / 11 | — |
| Python | 3.10 以上（本机已用 3.13） | 启动脚本会自动找，找不到才需要你装 |
| ffmpeg | 必须，用于抽帧与转码预览 | 命令行 `ffmpeg -version` |
| 显卡（可选） | N 卡，用于解码加速 | `nvidia-smi` |
| 磁盘 | 本地 SSD 留 2GB 以上（存数据库与缩略图） | — |

> **ffmpeg 是硬依赖**，没有它抽不了帧，分析会全部失败。
> 检查方法：打开命令行输入 `ffmpeg -version`，显示版本号即已安装。

## 二、启动方式

### 方式一：双击启动脚本（推荐，日常使用）

双击项目根目录下的 **`启动工作台.bat`**

它会自动完成五件事，全程不用你干预（模型下载那步会问一次）：

```
[1/5] 检查/创建虚拟环境 .venv
[2/5] 检查依赖，缺失就自动装（清华镜像源）
[3/5] 检查 YOLO 模型，缺失就问你要不要下载
[4/5] 检查端口 8501 是否被占用，占用就问你要不要关掉旧的
[5/5] 启动服务，健康检查通过后自动打开浏览器
```

看到这段就说明启动成功（浏览器会自动弹出）：

```
[1/5] 虚拟环境已就绪
[2/5] 检查依赖...
    依赖就绪
[3/5] 检查 YOLO 模型...
    模型已就绪
[4/5] 检查端口 8501...
[5/5] 启动服务...
============================================================
   工作台即将启动，浏览器会自动打开：

        http://localhost:8501

   · 这个窗口要一直开着 —— 关掉它就等于停止服务
   · 停止服务：在本窗口按 Ctrl+C，或运行 停止服务.bat
   · 首次使用请先到「设置与扫描」页填写视频源目录与回收目录
============================================================
```

**要点**：服务就跑在**这个黑窗口里**，日志也打在这里。窗口可以最小化，但**关掉就等于停服务**。启动时如果出问题，报错信息会直接显示在这个窗口里。

**如果浏览器没自动弹出**，手动访问 **http://localhost:8501** 即可。

### 方式二：命令行启动

```bash
cd E:/code/video-search
.venv/Scripts/python.exe -m streamlit run src/ui.py --server.port=8501
```

适合想看实时日志、或需要换端口的场景（把 `8501` 改成别的数字）。

### 方式三：只跑分析，不开界面（超大批量时用）

```bash
.venv/Scripts/python.exe -m src.cli scan    --root E:/监控/2024 --limit 500
.venv/Scripts/python.exe -m src.cli analyze --limit 500
.venv/Scripts/python.exe -m src.cli stats
.venv/Scripts/python.exe -m src.cli export  --out 清理清单.csv
```

命令行与网页共用同一个数据库，可以随时交替使用：白天用命令行跑分析，晚上开网页审核。

## 三、首次运行会发生什么

1. **创建 `.venv`**（约 10 秒）—— 独立虚拟环境，不污染你其他 Python 项目
2. **安装依赖**（约 1-2 分钟）—— streamlit / opencv / numpy 等，刻意不依赖 torch，包很小
3. **下载 YOLO 模型**（约 12MB，可选）—— 从 GitHub 下载。网络不稳时脚本会自动断点续传重试

> 模型这步可以跳过，但**强烈建议下载**。没有模型时程序只会做画面动静检测，认不出人和车，判定准确度会大打折扣。
> 跳过之后想补，随时双击 `download_model.bat`。

## 四、完整使用流程

### 第 1 步：配置路径（「设置与扫描」页）

| 配置项 | 填什么 | 注意 |
|-------|-------|------|
| **视频源根目录** | 移动硬盘上的年份目录，如 `E:\监控` | 程序只读，不会改你的文件 |
| **分级回收目录** | 如 `E:\_监控回收` | ⚠️ **必须与源同一物理盘** |
| **本地工作目录** | 如 `E:\code\video-search\data` | 数据库和缩略图都在这，放 SSD |

**为什么回收目录必须同盘**：跨盘移动等于"复制 10TB 再删除"，在 USB 移动硬盘上要跑几十小时。同盘移动只是改个目录记录，瞬间完成。填错了程序会直接拒绝执行并提示你。

填完点 **💾 保存配置**。

### 第 2 步：扫描 + 分析

点 **🔍 启动扫描（后台）** → 等它跑完 → 点 **🤖 启动 AI 分析（后台）**

- 两个任务都跑在**后台线程**里，启动后可以随意切换页签、继续审核其他视频
- 「执行进度」页和下方面板会每秒刷新：已处理数、速度（个/秒）、预计剩余时间
- 随时可点 **⏹ 停止任务**，会在当前文件处理完后收尾，已完成的写入不丢
- **先小批量试点**：处理上限先填 200，看判定效果满意了再放大

> 改了阈值要先点「保存配置」再启动任务，否则用的还是旧配置。

### 第 3 步：审核（「审核工作台」页）

队列按保留价值分**升序**排列——最可疑的排最前面。每条显示：

- 左侧：九宫格缩略图（带模型画出的检出框）
- 右侧：**判定依据链**，逐项说明每一分是怎么加的
- 底部：三个处置按钮

**键盘快捷键**（审核效率的关键，几万条时差别巨大）：

| 按键 | 作用 |
|------|------|
| `空格` | 确认清理（移入回收目录，可撤销） |
| `回车` | 标记误判，这段要保留（自动归因） |
| `←` `→` | 上一条 / 下一条 |
| `P` | 用系统播放器打开原视频 |
| `V` | 生成网页可播预览 |

> 快捷键失效时先点一下页面空白处再试（焦点在输入框里时快捷键会自动让位，避免打字被抢键）。

### 第 3.5 步：音频复核（推荐判删前开启）

画面"无人无车"≠ 没内容：画外通话、对讲、询价、警报等声音事件同样会被录进音轨，
这类片段画面判定会建议清理，但声音里记录了真实事件，删了就丢。**音频复核**就是
清理前多听一耳朵：

1. 在「设置与扫描 → 🔊 音频复核」**启用**并点**引擎自检**（首次需先装好引擎，见下）
2. 点**启动音频复核（后台）** —— 任务只处理"判定删除 + 有音轨 + 未复核"的候选，
   自动跳过已复核与无音轨片段，可随时停止，断点续跑
3. 回到「审核工作台」，右栏会显示**音频复核卡**：
   - 🔴 检出人声（含语音占比）或 ✅ 未检出有效人声
   - 📝 转写全文（展开查看，供你确认画外说了什么）
   - 🤖 LLM 参考结论（启用后）：可能有用 / 基本无用 / 不确定
   - 🔊 可播放抽出的音频
4. 复核结果与清理按钮联动：**有音轨但未复核的片段，一键清理会被拦下**，
   要求你明确勾选"已人工确认"后才放行 —— 防止画外有人声的片段被误删

**一次性安装（新功能首启前）**：

```
python scripts/setup_audio_engine.py          # 装 FunASR 依赖（绕开 numpy<2 坑）
python scripts/download_audio_models.py       # 下载阿里 ASR 模型（ModelScope 国内源 ~1.2GB）
```

- 引擎可插拔：`funasr`（阿里，默认）或 `faster_whisper`（兜底，见开发计划 3.6）
- LLM 有用性判断需要本机装 **ollama** 并拉取模型：`ollama pull qwen3:4b`
- 全程**不删除、不移动任何用户文件**；LLM 结论只是参考，最终由你拍板

### 第 4 步：批量处理（「批量浏览」页）

九宫格分页多选，适合处理明显成片的同类片段。批量移动后**自动生成清单 CSV 与空间统计**。

- **跳转**：底部「跳到第几页」直接输页码（还有首页 / 末页按钮）—— 条目多时不用一页页翻
- **筛选**：`仅看检出人声` / `仅看检出人物` / `最低分 ≥X`，与审核台同一口径
- **审核台**（逐条看的那页）同样有 `跳到第 N 条` / `跳到分数 ≥X` 和同一组筛选，
  换筛选条件会自动回到第一条

### 第 5 步：手动删除（你来做）

程序把文件移到了回收目录，按置信度分好档：

```
_监控回收/
├── A_高置信_可批量删除/     ← 看缩略图确认后直接全选删除
├── B_低置信_建议抽查/       ← 抽查后再删
└── _reports/
    ├── 移动清单_xxx.csv      ← 原路径/新路径/判定依据/分数
    └── 空间统计_xxx.txt
```

**关键预期**：文件被移动后**磁盘空间不会释放**——它们只是换了目录。只有你手动删除之后，空间才真正回来。这是"数据唯一一份"必须付出的代价：任何误操作都还有反悔的余地。

### 第 6 步：根据误判调参（「误判分析」页）

每次标记「误判，这段要保留」，系统会回看模型的原始检出（包括那些没过阈值的），自动归类原因：

- 低置信度漏检 → 建议调低 `yolo_conf_threshold`
- 夜视/红外画面 → 需要单独校准
- 目标太小/遮挡 → 建议提高抽帧数

攒够一定量后按页里的建议调阈值，重新分析即可。

## 五、停止与重启

**停止**（任选一种）：

- 在启动窗口里按 `Ctrl+C`
- 直接关闭那个黑窗口
- 双击 `停止服务.bat`（适合窗口找不到了的情况）

**重启**：再次双击 `启动工作台.bat`。它会检测到端口被占用并问你要不要关掉旧的，选 Y 即可。

**数据不会丢**：所有进度都写在 `data/videos.db` 里，随时停、随时续跑。

## 五之二、开机自启与防休眠

### 装机后自动启动

双击 **`开机自启-安装.bat`**，之后每次登录 Windows 会自动延迟 30 秒启动工作台
（实现方式：系统「计划任务」→ 登录时触发，不是往启动文件夹塞快捷方式，所以
可控、可查、可撤）。取消就跑 **`开机自启-卸载.bat`**。两个脚本都需要时会提示
"以管理员身份运行"。

手动验证（不必重启）：`schtasks /Run /TN "监控视频AI筛选工作台"`

### 任务运行期间禁止休眠

**已内置，不用你操心。** 后台任务（扫描 / AI 分析 / 音频复核 / 精华剪辑 / 一键执行）
一启动，程序就会向 Windows 申请「禁止系统休眠」，任务结束自动释放；异常退出也会
释放，不会把你的电源计划改坏。

- 申请期间**屏幕照常会关闭/变黑**（只是系统不睡），省电且不烧屏。
- 用的是 `SetThreadExecutionState`，只对**当前任务**生效，**不改动**你的电源计划，
  也不影响你手动合盖/点开始菜单休眠。
- 任务开始时「执行进度」页的日志会写一行 `已申请「禁止系统休眠」`，
  没看到这行说明申请被系统策略拦了，此时请自行确认电源设置。

**查看/修改你自己的睡眠超时**（与本程序无关的全局设置）：

```powershell
powercfg /q SCHEME_CURRENT SUB_SLEEP STANDBYIDLE   # 查看当前值（秒）
```

### 跑长任务时电脑还是睡了？

按可能性从高到低排查：

1. **是"休眠"不是"睡眠"**——本程序挡的是「自动睡眠」；若你的计划里配了
   「在此时间后休眠」（`HIBERNATEIDLE`），也已被同一个申请挡住。可对比
   `powercfg -requests` 看当前有哪些"电源请求"（在任务运行时执行）。
2. **笔记本合盖**——合盖动作走的是独立设置，程序管不了。把「合上盖子时」设为
   「不采取任何操作」，或跑任务时别合盖。
3. **任务其实已经跑完了**——释放后系统按你的超时正常入睡，这是预期行为。

## 六、常见问题

### 启动时报"端口已被占用"
上次的工作台没关干净。启动脚本会自动检测到并询问是否关闭旧服务，选 Y。
手动处理：双击 `停止服务.bat`。

### 依赖安装失败
多是网络问题。手动执行（换回默认源或换镜像）：
```bash
.venv/Scripts/python.exe -m pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple
```

### 模型下载失败
GitHub release 的 CDN 有时被代理掐断。多试几次（脚本会断点续传），或双击 `download_model.bat` 重试。
实在下不动就手动下载放到 `data\models\yolov8n.onnx`：
`https://github.com/ultralytics/assets/releases/download/v8.4.0/yolov8n.onnx`

### 分析全部失败，提示"无法解码"
是 **H.265+/Smart H.265 私有编码**（海康/大华常见）。程序对解不开的片段**一律判为保留**，绝不会因技术原因误删——这是设计好的安全兜底。

### 网页里视频播不了
正常。Chrome/Edge 播 H.265 依赖硬件解码，私有编码更不认。点 **V** 键生成 H.264 预览即可播放，日常审核看九宫格缩略图就够了。

### 分析速度很慢
- 确认 ffmpeg 支持硬件解码（有 N 卡会走 CUDA，快数倍）
- 移动硬盘是 USB 机械盘的话，10TB 纯顺序读就要 25 小时左右，属正常现象，分批跑即可
- 降低「每个片段抽帧数」（设置页，默认 6 帧，可降到 3 帧）

### 进度条不动了
先看「执行进度」页的后台任务面板：任务在跑的话，`已处理` 数字会持续增长。
数字不动且长时间没变化，常见原因是移动硬盘休眠或掉盘——检查硬盘连接。

## 七、文件都在哪

```
data/
  videos.db         SQLite 数据库（全部分析结果，唯一数据源）
  models/            YOLO 模型
  thumbs/            九宫格缩略图（人工审核看的是这些，不碰移动硬盘）
  temp/              临时抽帧目录
config.json          运行配置（路径、阈值、打分权重）
```

根目录的 `.bat` 脚本：

| 脚本 | 用途 |
|---|---|
| `启动工作台.bat` | 启动服务（日常用这个） |
| `停止服务.bat` | 窗口找不到了时用它停服务 |
| `下载模型.bat` / `download_model.bat` | 补下 YOLO 模型 |
| `开机自启-安装.bat` | 登录后自动启动工作台 |
| `开机自启-卸载.bat` | 取消开机自启 |

想备份分析成果，复制 `data/videos.db` 就够了。

## 八、安全红线（务必记住）

1. **程序永不删除任何文件** —— 只做分析、打分、分级移动。代码里有自动审计确保这一点。
2. **回收目录必须与源同盘** —— 否则移动会变成复制 10TB
3. **所有移动都可撤销** —— 「执行进度」页底部有按批次撤销
4. **空间在手动删除前不会释放** —— 提前对齐预期
5. **数据唯一一份时，先备份再做筛选** —— 程序再安全也防不住硬盘本身出问题。10TB 数据躺在要连续读写 25 小时的移动硬盘上，这个风险与程序怎么写无关
