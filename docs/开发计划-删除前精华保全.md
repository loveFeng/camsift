## 0. 一页摘要

**你的原话定了这次的方向**：「我是想将需要删除的视频更好的做一下精华剪辑，因为删除后就再也找不到了。」
⇒ 精华剪辑不是"省得你多看一眼"的附属品，它是**原片被删之前的最后一道保全**。评价标准因此从
"准确率"变成**"召回率 + 覆盖面"**。

**已拍板**：① 整片静止 = 无人（不补检）；② L1 提精度用**多帧一致性**。

**实测查出四个丢件点，其中三个是代码结构造成的、可以零算力修掉**：

| 编号 | 丢件点 | 规模 | 性质 |
|---|---|---|---|
| **D1** | C 级只留一张静帧，**不切 mp4** | 476 段 / 67.3 分钟 / 涉及 394 条视频 | 改 1 行 |
| **D2** | **粗扫检出被精扫否决后，直接丢弃** | **5,215 条命中（27.2%）**；其中 **474 条视频"粗扫看到了东西、最终零产物"** | 改合并逻辑 |
| **D3** | "低置信度疑似"这一档**结构性产出 0 条** | 476 个 C **全部**是纯动静（conf=0），conf>0 的 **0 条** | D2 的同一根因 |
| **D4** | L1 报过有人、L2 只给了一张静帧 | 57 条视频 | D1 的后果 |

**其中 D2 是最值钱的修复**：474 条视频在删除后**一个字都不会留下**，而粗扫明明检出了目标。

**三条轨**：

| 轨 | 做什么 | 工时 | 机器成本 |
|---|---|---|---|
| **Track C**（主） | 粗扫疑似不再丢弃 + C 级也切 mp4 + C 级不进人工队列 | ~5h | 重剪 **816** 条 ≈1.5h；新增产物 ≈15GB |
| **Track A** | L1 统一 CLAHE + 多帧一致性（先校准后生效） | ~8h | 校准实验 ≈1h |
| **Track 0** | 「无精华」拆成三义（尺子） | ~2h | 0 |

**合计 ≈ 17 小时**（按每周 10h ≈ 2 周）。**建议顺序：Track 0 → Track C → Track A**。

> ⚠️ **Track A 与 Track C 必须同批上线**：L1 收紧（多帧一致性）会把更多视频推进"待删除"，
> 也就更依赖 L2 兜底。只做 A 不做 C，等于把安全网收紧的同时提高了坠落概率。

## 1. 目标

1. **删除前最大化保全**：处置候选（要删的视频）里，凡是**有任何目标信号**的时间段，都要留下
   **可播放的视频**，而不是只有一张静帧或被丢弃。
2. **不反噬减负**：保全量上升，但**人工要看的量不上升**（C 级作为档案存在，不进审核队列）。
3. **数字可解释**：「无精华」要能说清是"真复核过没有"、"预筛跳过（已接受的口径）"、
   还是"粗扫看到了但被否决"。
4. L1 提精度用**多帧一致性**，且**真人漏检增量 = 0**（硬指标）。

**非目标**：全库降阈值 / 全量加密检测（成本 14–54 倍，已证伪）；盲区补检（已拍板不做）；
引入 VLM 兜底；给视觉链路引入 torch；任何删除类操作。

## 3. 丢件点与根因

### 3.1 根因：粗扫的"疑似"被精扫否决后就消失了

```
粗扫  640 / conf 0.15   →  检出 person（conf 落在 0.15~0.35 的噪声区）
                              ↓  build_windows 圈出候选窗
精扫 1280 / conf 0.25   →  同一位置 conf 反而下降（实测 0.42 → 0.19），未达 0.25
                              ↓  highlighter.py:591-600 合并逻辑
                            「落在已精扫窗内 + 精扫没确认」⇒ **直接丢弃，不降级**
```

后果有两层：
- **D3**：`C 级 = 低置信度疑似 或 纯动静` 这个定义里，**前半支永远为假** ——
  476 个 C **全部**是 `motion_only`（conf=0.0）。也就是说"看到过但不敢确认"的信号，一条都没留。
- **D2**：整条视频若所有粗扫检出都被这样丢弃，`hits` 为空 ⇒ `events` 为空 ⇒ **判「无精华」** ⇒
  自动移入回收目录。**474 条视频就是这么变成"零产物"的。**

> 讽刺的地方在于：粗扫**看低分辨率时看到的**、精扫**看高分辨率时否定的**，按常规该信精扫；
> 但你的应用场景是"删除前最后保全"，唯一正确的偏置是**宁可多留**——
> 应该把这条信号**降级保留**（留成 C 疑似 + 一段 mp4），而不是丢弃。

### 3.2 D1 / D4：C 级只有静帧

`highlighter.py:647-650`：`mp4 = None`，只有 `grade in ("A","B")` 才切视频。
设计初衷是"C 级是垃圾，jpg 几乎不占空间，万一有半张脸物证还在"——这个初衷是**为省空间**的，
与"删除后再也找不到"的新目标冲突。**476 段 / 67.3 分钟的视频内容，现在只剩 476 张图**，
其中 57 条视频的 L1 还明确报过有人。

### 4.2 Track A —— L1 精度（多帧一致性，~8h）

**A1 消除增强口径漂移**：CLAHE 抽成公共 `enhance_clahe(frame, clip, grid)`，
`highlighter._enhance()`（现含 CLAHE 的 LAB-L 通道实现）改为调用它 —— **一处实现两处调用**。
L1 在 `analyzer.analyze_one()` 的检测循环里接上；新配置 `analysis.clahe` / `clahe_clip`。

**A2 判据改为多帧一致性**：`analyze_one` 逐帧统计 `person_frames`（该帧存在 person 且 conf ≥ 阈值的帧数），
随 `build_decision(...)` 传入；`has_person = 1` 需 `person_frames >= analysis.person_min_frames`
（默认 1 = 现状，**P1 落地时不改变行为**，等校准报告再调）。
> 为什么优于单纯抬阈值：真人移动会**连续多帧**命中，杂物误报多为**单帧闪烁**。
> 抬阈值会把"只在一两帧出现、conf 0.3–0.4 的真人"一起干掉；多帧一致性区分的是**稳定性**。

**A3 校准实验**（`scripts/calibrate_l1.py`，新）：分层抽 300 条
（① 有 A/B 精华 100 条 ② 无精华·已检测 100 条 ③ 盲区+L1 报有人 100 条），
跑 5 种策略（S0 现状 / S1 抬阈值 0.5 / S2 `person_min_frames≥2` / S3 CLAHE+S0 / S4 CLAHE+S2），
产出《L1 校准报告》：每组的误报率 / 漏检率 / 待办计数变化。

**A4 可重跑**：`analyzer.analyze_one()` 取的是 `path = Path(row["path"])`，而 `mover.py` 只写 `trash_path`
⇒ 已搬入回收的原片**跑不了**。抽 `_resolve_src(row)`（`path` 缺失回落 `trash_path`，
**照抄 `audioreview.review_one` / `highlighter.cut_one` 的既有做法**）。新增 `reanalyze_queue()` + `analysis_version`。

### 4.3 Track 0 —— 观测口径（尺子，~2h）

「无精华」拆成**三义**（此前是两义，现补上 D2 这一义）：

| 分义 | 谓词 |
|---|---|
| 已检测·确实没有 | `highlight_clips='[]' AND coarse_sent>0 AND coarse_hits=0` |
| 预筛跳过（**已接受的口径**） | `coarse_sent=0` |
| **粗扫看到过但被否决**（D2） | `coarse_sent>0 AND coarse_hits>0` |

- 落库 `videos.highlight_sent`（粗扫实际送检帧数）；history 用一次性脚本从 `manifest.jsonl` 回填。
- 「精华复核」页显示三个数；Track C 上线后第三个数字应显著下降。

## 10. 风险与回滚

| 风险 | 影响 | 对策 |
|---|---|---|
| C 级 mp4 让产物膨胀 | G 盘只剩 71G | `c_cut_mp4` 开关；分批重剪；必要时只对 `n_person>0` 或 `level=suspect` 的 C 段开 |
| 粗扫疑似全留 ⇒ C 级虚增（噪声被当物证） | 档案噪音大 | **C 级不进审核队列**（C3）是关键前提；C 是"档案"不是"待办" |
| L1 收紧 ⇒ 更多视频进入待删 | 更依赖 L2 兜底 | **Track A 与 Track C 同批上线**（§0 的警告） |
| 抬精度导致真人漏检 | 违背"宁可多留" | 主手段用多帧一致性而非抬阈值；校准报告硬指标"漏检增量 0"；放行只到回收目录、可撤销 |
| 重剪覆盖旧产物 | 数据丢失 | 重剪产物加 `_id` 后缀（既有逻辑 `highlighter.py:652-653` 已有）；`hlv2` 目录与旧产物分列 |
| 原片已被手动删除 | 重剪无法执行 | 执行前探测存在性，缺失则跳过并计入报告（照 `archiver` 的"缓存缺失跳过"） |
| 历史行阈值不一致（现存 `has_person=1 / person_conf=0.3` vs 当前阈值 0.4） | 统计口径混乱 | 用 `analysis_version` 标记；未重跑的行在报告里注明 |

**回滚**：所有行为改变都由配置键控制（`keep_coarse_suspect` / `c_cut_mp4` / `clahe` /
`person_min_frames`），退回默认值即回到当前行为；代码层只增列、不改列。
