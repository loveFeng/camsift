# 监控素材「画面精华」自动剪辑系统 — 方案说明

> 版本 **v2** / 2026-09-08 / 状态：**已落地（工作台 L2.8 层），全量待执行**
>
> 目标：在删除低价值监控录像之前，把画面里还有点东西的几秒自动剪下来留存，
> 与已实现的「语音档案归档」合起来构成删除前的最后一道保险。

## 一、结论先行

这套东西的本质**不是剪辑，是检索 + 切割**。

剪辑软件（剪映/PR）解决的是"已知素材怎么拼好看"，而你的问题是反过来——
**不知道素材里哪几秒有价值**。所以核心不在剪辑工具，而在一条把
「17.9 小时 → 几百个可用片段」的检测流水线。

```
粗扫抽帧 → CLAHE → 帧差预筛 → 检测(0.15) → 候选窗
        → 精扫抽帧 → 检测(0.25) → 事件聚合 → 分级 → 切割/抽帧 → 复核页签
```

**全自动，不需要人工二筛。** 机器把不确定性表达在目录结构里（A/B/C 三级），
你想看就看 A 级，不看也无所谓——这是 v1 到 v2 最大的设计变化。

## 二、素材底数（实测，非估算）

| 指标 | 实测值 |
|---|---|
| 待处理（已判 trash 待删） | **1372 个 mp4** |
| 总时长 | **17.9 小时** |
| 单文件时长 | 平均 47s |
| 编码规格 | H.264 / 1280×720 / **15fps** |
| 命名规则 | `YYYYMMDDHHMMSS_010.mp4`（含真实拍摄时间，通道号 010） |
| 月份分布 | **2015-12 占 1321 段（96%）**；2015-06~11 合计 51 段 |
| 时段分布 | 夜间(18–06) **73%**；其中 19–21 时集中 894 段（65%） |
| 机位 | 鱼眼门镜摄像头，广角形变明显 |

环境现状：ffmpeg 8.1 ✅、Python 3.13 ✅、**无 NVIDIA 独显（纯 CPU 推理）**。

### v1 的两处结论被实测推翻

1. **规模不是 88 分钟，是 17.9 小时。** v1 基于 113 段抽样，实际全量 12 倍。
   这直接否掉了"一把梭 20 分钟"的工期估算。
2. **不是 94% 夜间红外。** 按文件名时间戳统计，夜间占 73%，另有 27% 是彩色
   昼间画面（室内开灯/自然光）。v1 的"红外热源更亮"假设只在夜间那部分成立。
   两类素材混跑已被 30 样本验证覆盖，无需分批处理。

### 一个必须先摊开的信号

L1 判定结果里，1372 段中 **83% 的 `retention_score = 0`，且 `near_miss` 为 0/1372**。
`near_miss` 记录的是"模型看到了人但置信度没过阈值"——一条都没有，意味着在 L1
的视角里这批画面是真空的。

这个数字指向两种相反的可能：画面确实空，或者模型在低照度下瞎了。
**这正是本功能存在的理由**：用 8 倍于 L1 的采样密度独立复核一遍，
用数据回答"到底有没有东西"。

## 三、关键约束

### 3.1 L1 采样密度不足（本功能的第一动机）

L1 每段只抽 12–16 帧。43 秒 × 15fps = 645 帧，**只有 2.5% 的画面被看过**。
审核台上那张九宫格就是这 16 帧拼的，人工审核实际看的就是这 2.5%。

小孩身形小、进出画面快，或者被门框家具挡住只剩半个身子——这种密度必然漏。
**所以"人已经审核过一遍"兜不住这个漏。** 自动化高密度检测不是重复劳动，
是替人补上没看过的那 97.5%。

样本验证已证实：一条 L1 判 0 分的视频里，两级检测捞回了**穿粉红色衣服的小孩**。

### 3.2 低照度掉点

COCO 训练的通用检测器在低照度画面上 person 类明显掉点。三重对冲：

- **CLAHE 预处理**（必开）：对比度受限自适应直方图均衡，拉开信噪比
- **帧差预筛提供第二路证据**：不依赖模型，纯像素差分
- **阈值下调**：误检代价远小于漏检——漏掉的家庭影像找不回来

### 3.3 固定机位 = 帧差预筛的理想工况

固定机位、无云台运动，背景几乎恒定。先用帧间差分找出"画面有变化"的时间窗，
只对这些窗口跑检测。**样本实测省 93% 算力**（4042 帧只送检 267 帧），
远好于 v1 预估的 40–60%。

> 备选方案（已评估，不采用）：
> - **OpenCV HOG 行人检测**：零依赖，但低照度下几乎失效
> - **纯背景减除**：能定位运动，但分不清人/宠物/拖把/光影，只能做候选区间
> - **微调红外专用模型**：效果最好，但为家庭素材做模型微调属于过度工程

## 四、两级检测（v2 核心设计）

### 为什么不能单级

| 方案 | 单视频推理 | 全量 1372 段 |
|---|---|---|
| 2fps @640（v1 原设计） | 11 s | ~4.3 小时 |
| 2fps @1280（全片精扫） | 46 s | ~17 小时 ❌ |
| **两级：粗扫 + 精扫** | **~7 s（实测）** | **~2.7 小时** ✅ |

直接把全片拉到 1280 精扫是 17 小时，不现实。两级能在 1/6 的代价下拿到接近的召回。

### 两级分工

| 级 | 参数 | 范围 | 职责 |
|---|---|---|---|
| 粗扫 | **3fps @640，conf 0.15** | 全片 | 负责**不漏**，误检交给下一级 |
| 精扫 | **4fps @1280，conf 0.25**，窗两侧各扩 2s | 仅候选窗 | 负责**看清**，小目标全靠它 |

粗扫阈值压到 0.15 是故意的：**误检的代价是被精扫过滤掉（多花点算力），
漏检的代价是家庭影像永久消失。这两件事不对等。**

### 精扫预算控制

精扫帧数上限 = 粗扫帧数 × `max_fine_ratio`（默认 1.5）。超预算时按粗扫得分
从高到低优先精扫。**被预算跳过的窗不会当作"已复核"丢弃**——它们的粗扫检出
保留为 C 级疑似（要求该帧确实有动静，静态画面上的疑似基本是噪点）。

样本实测：精扫否决了 5 段粗扫误报，两级协作真实生效。

## 五、事件聚合与三级产出

### 5.1 离散帧 → 事件

| 参数 | 取值 | 说明 |
|---|---|---|
| `gap_merge` | 3.0 s | 间隔小于此值的有检帧合并为同一事件（抵消遮挡抖动） |
| `min_duration` | 1.0 s | 短于此的事件丢弃 |
| `pre_pad` | 2.0 s | 起点前移，避免人物"半路冒出来" |
| `post_pad` | 3.0 s | 终点后移，动作收尾完整 |
| `max_clips_per_video` | 8 | 单视频最多切几段（按价值排序） |
| 边界钳制 | [0, 时长] | 防止越界 |

### 5.2 三级产出（用目录结构代替人工筛选）

| 目录 | 判定条件 | 产物 |
|---|---|---|
| `A_确认/` | 精扫确认有目标，**且 ≥8s 或 ≥2 人同框** | mp4（含原音）+ 代表帧 |
| `B_短暂/` | 精扫确认有目标，但 <8s 且 <2 人 | mp4（含原音）+ 代表帧 |
| `C_疑似/` | 置信度 0.15–0.25 疑似，**或只有大幅动静**（开关门/物品倒地） | **仅 1 张代表帧 jpg** |

**C 级只留静帧是关键取舍**：全自动必然产生垃圾，但垃圾以 jpg 形式存在几乎
不占空间（1372 段全命中也就 0.5 GB），而万一里面有孩子的半张脸，物证还在。

> 注：v1 的 C 级定义是"<2s 丢弃"，v2 已改为"疑似但留证"，语义完全不同。

## 六、切割与编码（这里有必踩的坑）

**坑**：监控 H.264 的 GOP 很长。用 `-c copy` 流复制，ffmpeg 只能把切点吸附到
最近关键帧，误差可达数秒，开头还可能花屏/绿帧。监控素材上这个坑是必踩的。

**解法**：每个事件**重编码**切片，换取帧级精确。

```
ffmpeg -ss <start> -i <src> -t <dur> \
  -c:v libx264 -crf 20 -preset veryfast -r 15 \
  -c:a aac -b:a 128k -g 30 -movflags +faststart <out>
```

- `-crf 20`：视觉近无损，体积可控
- `-r 15`：**保持源帧率，绝不升帧**。15fps 素材拔到 30fps 徒增体积且无新信息
- `-g 30`：输出关键帧间隔 2 秒（15fps × 2s），便于拖动预览
- `-movflags +faststart`：边下边播

**输出命名**：`<年份>/<级别>/<源名>_E<序号>_<级别>_<HHMMSS>_<时长>s.mp4`

**同盘是提示，不是限制**：输出目录与源盘/回收盘同盘时给出黄色警告，但**允许执行**——
删除是手动操作，用户清楚自己在删哪个文件夹，决定权留给人。
启动时只拦截真正的硬错误（`is_drive_root`：空目录 / 盘符根目录 / 缺 ffmpeg / 缺模型）。

## 十、运行 SOP

### 日常路径：一键执行（ADR 0004，推荐）

> 决策记录见 `docs/adr/0004-one-click-pipeline.md`。六个阶段原本各一个按钮、
> 散在设置页四个段落和审核台顶部，做一批要上下跑六趟。现在参数配一次、点一下到底。

0. **设置页最上方「⚡ 一键执行」区**
   - ① 路径：源目录 / 回收目录 / 本地工作目录 / 模型 / 语音档案目录 / 精华目录
   - ② 分析参数：目标检测阈值、抽帧数、YOLO 开关
   - ③ 本次要跑什么：本次导入上限（**只限制扫描**）、六个阶段开关（默认全开）
   - 点「⚡ 一键执行（跑完到「回收目录就绪」）」—— 前置条件一次性检查，缺什么直接
     拒绝启动并列出缺什么（不会跑半截）

   链路顺序**由依赖决定**，不可调换：

   ```
   扫描 → AI 分析 → 音频复核 → 语音归档 → 批量放行 → 画面精华剪辑（含自动处置）
   ```

   | 约束 | 原因 |
   |---|---|
   | 分析在音频复核/剪辑之前 | 两者的队列都只认已判定的 `trash/review` |
   | 音频复核在语音归档之前 | 归档的数据源是复核产出的转写与缓存 wav |
   | **放行在剪辑之前** | 剪辑的自动处置会搬走未处置候选，而放行队列只认未处置 —— 反序放行就是空操作 |

   - **只有扫描分批**：上限只管"本次导入多少新料"；其余阶段跑全库队列（都带幂等标记），
     所以点一次会顺带把历史积压一起清掉，第二次点也不会重复劳动
   - **失败语义**：单条坏文件只记录并继续；某阶段整体失败（引擎未就绪/目录非法/抛异常）
     立即停下、不跑下游（上游失败让下游空跑，比停下更危险），面板写清停在哪一步
   - **停止** = 当前文件收尾后不进入下一阶段；**再点一次** = 从断点续跑
   - 跑完 = 回收目录就绪。人只剩两件事：翻「精华复核」页看 A/B 产物、
     **手动清空回收目录**

1. **先跑语音档案归档（L2.7）**（分步执行时的顺序）
   有人声的片段可能还躺在 `G:\need-del` 里。纯文件复制 + 转写，几分钟的事。
   排在精华剪辑之前——它是更确定的收益。

2. **（可选）再跑一次样本验证**
   ```bash
   ./.venv/Scripts/python.exe scripts/_legacy/sample_highlight.py 30
   ```
   改过参数后用来定心，干跑不落库。

3. **全量跑**
   工作台 → 「设置与扫描」→ 🎞 启动画面精华剪辑。
   后台约 2.7 小时，可在「执行进度」页签看进度。

4. **验收**
   「精华复核」页签按 A/B/C 浏览：缩略图 + 真实拍摄时间 + 时长 + 置信度，
   支持直接播放和定位文件。

5. **确认后再清空 `G:\need-del`**
   在此之前，音频已归档、画面精华已留存，可以放心删。

> 「剪精华 → 决定去留」一并做完，人只看 A/B 级产物。决策记录见
> `docs/adr/0001-cut-then-delete-replaces-manual-review.md`。

6. **（可选，强烈建议）审核台先一键放行「无人」候选**
   放行候选 = 判删候选里**机器没看到任何人物信号**的片段：未检出人物，且
   `decision_trace` 里也没有"疑似人物未达阈值"（near_miss，漏检高发区）。
   动物/车辆不拦（权重只有人物的三分之一）。人眼盯的缩略图正是机器抽的那 16 帧，
   逐条审不产生任何信息。审核台页签顶部会出现「⚡ 审核减负：N 个「无人」片段可
   一键放行」，一键批量移入分级回收目录，之后由精华剪辑 8 倍采样密度兜底重扫。
   分数门槛（`verdict.release_threshold`，默认 30）只作保险丝 —— 判据是人物信号。
7. **音频口径：不拦，靠"事后补"**
   归档/剪辑/音频三个队列都已从「仅已移入回收目录」放宽为**处置候选** = 已移入
   回收目录 OR 未处置的 `trash/review`。所以放行**不必等**音频复核：放行后仍能补
   复核（`review_one` 有 `trash_path` 回落）、补归档，只要**没手清回收目录**。
   代价只有一条：**回收目录被手动清空前，把音频复核 + 语音归档跑完** ——
   一键执行的链路顺序（音频复核先于放行/剪辑）就是为它兜的底。
8. **精华剪辑剪完自动处置（`highlight.auto_dispose = True`）**
   单条剪完即决策，无需人工介入：
   - 精华占比 > `keep_full_ratio`(0.6) → 自动**整片保留**（切片丢上下文）
   - 已放行（human=trash）但剪出高占比 → 自动**撤销移动捞回**
   - 其余（含确认无精华）→ 自动**移入回收目录**（精华已留底）
   人只在「精华复核」页翻 A/B 产物；任务完成摘要会显示处置统计。
9. **在剩下的人里定位（跳转 + 筛选，ADR 0005）**
   放行之后待审核只剩几百条，但审核台只能一条条翻、九宫格只能一页页翻，
   看分数最高那几条要从头点到尾。现在：
   - **审核台**（每页 100 条）：`跳到第 N 条`、`跳到分数 ≥X`、
     `仅看检出人物` / `仅看检出人声` / `最低分 ≥X` 筛选，可一键清除筛选
   - **批量浏览**（每页 24 条）：`跳到第几页` + 首页 / 末页
   - 两页共用同一套筛选谓词：在批量浏览里看到的条目，审核台里能按同样口径找到
   - 越界跳转自动夹住（条号超总数→末尾，页码超总页数→末页）；
     换筛选条件后自动回到第一条，不会停在旧位置上半死不活
10. **最后手动清空回收目录**（程序永不删除，只 move/undo）。

## 十一、风险与边界

1. **低照度漏检**：最大风险。已用 CLAHE + 帧差双路 + 两级检测 + 低阈值四重对冲。
   全量跑完后建议抽看 A 级，据此回调 `coarse_conf`。
2. **误检**：低照度噪点、衣架、拖把可能被当人。C 级只留静帧，代价可控。
3. **切割精度**：必须重编码，不能 `-c copy`（见第六节）。
4. **算力**：全量约 2.7 小时，纯 CPU。中途可停，已完成的不重跑（幂等）。
5. **隐私**：全程本地处理，不上传任何云端服务。素材含家庭生活影像，这点写死。
6. **15fps 低帧率**：输出保持 15fps。慢动作需要 60fps 源，本素材不具备条件。

## 十二、后续可扩展（当前不做，留接口）

- **人脸识别聚类**（insightface）：按家人分组，一键生成"某人的年度合集"
