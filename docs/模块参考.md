# 模块参考

> **状态：现行** ｜ `src/` 逐模块的职责与公开 API。**签名真源 = 代码**，本文只列"谁在什么条件下调它、
> 它保证什么"。想知道数据字段看 [`数据模型.md`](数据模型.md)，想知道部件怎么连起来看 [`架构设计.md`](架构设计.md)。
> 规模约 7,800 行 / 15 个模块（`ui.py` 占约四分之一，其余都在几百行量级）。

调用约定（全模块通用）：

- **进度回调三件套**：`progress(done, total, name)` / `log(msg)` / `stop_event`
  —— 批量入口一律接这三个，由 `jobs.Job` 提供，所以"手点按钮跑"和"一键执行跑"行为完全一致。
- **失败语义**：单条失败**记 `*_error` 后继续**；阶段级失败（引擎没装、目录非法）**抛异常**。
- **只读源盘**：所有模块对 `path` 指向的文件只读，唯一的写操作在 `mover`。

## `config.py` —— 配置层

| API | 说明 |
|---|---|
| `load_config(path=None)` | 读 `config.json`，与 `DEFAULT_CONFIG` 深合并（增删配置项不会让旧配置失效）。**损坏自愈**：0 字节/半截 JSON → 按 `config.json.bak` → `*Conflict*.json` → 默认 的顺序恢复，损坏件留档为 `config.json.corrupt-<时间戳>`，并通过 `LAST_NOTICE` 告知 UI |
| `save_config(cfg, path=None)` | **原子写**：临时文件 + `fsync` + `os.replace`，随后才更新 `.bak`（让 `.bak` 恒等于"最后一份确认有效的配置"） |
| `ensure_dirs(cfg=None)` | 只创建本地工作目录 / 缩略图 / 模型 / 库目录，**绝不创建或改动源盘目录** |
| `bin_path(cfg, "ffmpeg_path"\|"ffprobe_path", "ffmpeg"\|"ffprobe")` | 配置指定优先、其次 `PATH`；找不到返回 `None`。**五个模块都必须用它**，各写一份 `which` 迟早有一份漏掉配置里的自定义路径 |
| `detect_sync_risk(path)` | 沿路径向上找网盘标记（Synology / Dropbox / OneDrive / 坚果云…）。网盘双向同步会在写入中途把库覆盖回去，几天的分析结果可能凭空消失 |
| `COCO_CLASSES` | COCO 80 类名称（YOLOv8 官方顺序），把类别 id 翻成人话 |

## `db.py` —— SQLite 数据层

`Database(db_path)`：构造时 `init_db()` → 建表 + `_migrate()` 补列（幂等）。

- **写入**：`upsert_video_meta()` / `update_analysis()` / `update_audio_review()` / `mark_audio_skipped()` /
  `set_human_decision()` / `log_action()` / `add_feedback()` / `mark_archived()` /
  `mark_highlight()` / `mark_highlight_error()` / `reset_highlight()`
- **队列**（谓词真源，详见 [`数据模型.md`](数据模型.md) 第四节）：`review_queue()` / `audio_review_queue()` /
  `archive_queue()` / `highlight_queue()` / `rehighlight_queue()` / `release_queue()`
- **计数**（**必须与队列同口径**）：`count_review_queue()` / `count_review_below()` / `count_audio_pending()` /
  `count_archive_pending()` / `count_highlight_pending()` / `count_rehighlight_pending()` / `count_release()`
- **统计**：`stats()` / `space_report()` / `highlight_stats()` / `no_clip_breakdown()` / `feedback_summary()`
- **导出**：`export_csv()`
- **交叉核对**：`pending_highlight_ids()`（全库"还没剪完"的 id 集合 = 两条队列 ∪ 硬失败行）
- **只读扫描**：`recycle_scan_rows()`（取判定保全状态所需的最小列集，**绝不 `SELECT *`**）
- **无删除接口**（红线）。`conn()` 每次独立开关连接，避免 Streamlit 多线程复用连接的问题。

## `scanner.py` —— L1 元数据

| API | 说明 |
|---|---|
| `Scanner.scan(root, batch_name, limit, skip_existing, with_audio_energy, ...)` | 遍历源目录 → `ffprobe` → 入库。**串行读盘**（保护机械硬盘），断点续跑（`skip_existing`） |
| `iter_video_files(root, exts)` | 按扩展名递归列举 |
| `probe(path, ffprobe)` | 返回入库所需的元数据 dict；失败返回 `meta_ok=0` + `meta_error` |
| `parse_year(path, root)` | 从目录/文件名推年份，供回收路径分层 |
| `audio_energy(path, ffmpeg)` | `volumedetect` 的 `mean_volume`（dB）。**判据**：`scoring.audio_db_threshold`（默认 -50 dB）是实测的"环境底噪 vs 确实有动静"分界 |
| `find_ffprobe(cfg)` | 走 `config.bin_path` |

## `analyzer.py` —— L1 判定

| API | 说明 |
|---|---|
| `Analyzer.analyze_one(row, keep_thumb=True)` | 单条全流程：抽帧 → 动静 → YOLO → 打分 → 缩略图 |
| `Analyzer.run(batch_id, limit, progress, log, stop_event, refresh_every)` | 批量入口 |
| `extract_frames(path, n_frames, out_dir, ffmpeg, width, duration, timeout, hwaccel)` | 均匀抽帧。`hwaccel="auto"` 优先硬解 |
| `motion_ratio(frames)` | 前景面积占比（帧差），刻画"误触发指纹" |
| `frame_stats(frames)` | 亮度 / 对比度 / 饱和度 / 拉普拉斯方差（模糊度）+ `is_low_light` / `is_blurry`。**落库但不参与打分**，只用于 trash 文案解释与误判归因 |
| `YoloDetector.detect(frame, raw_min=0.15)` | OpenCV DNN 跑 ONNX，返回**含未达阈值**的检出（`raw_min` 以上都留证）。没有模型时 `available()` 为假，自动降级为纯动静检测 |
| `build_decision(detections_all, motion, audio_energy, has_audio, fstats, cfg, yolo_on)` | **判定核心**：逐项加权 → `retention_score` → `verdict` + `decision_trace`（含 `near_miss`）。人物权重最高，检出即保底 |
| `save_thumbnail(frames, video_id, cfg, detections=None)` | 写 `data/thumbs/<id>.jpg`，把检出框画上去 |

## `audioreview.py` —— L2.5 音频复核

`AudioReviewer(cfg)`，引擎可插拔（`audio.engine`：`funasr` 默认 / `faster_whisper` 兜底）。

| API | 说明 |
|---|---|
| `review_one(db, row)` | 单条：抽 wav → VAD → （VAD 漏检时降噪副本再 VAD）→ ASR → LLM 有用性 → 落库。有 `trash_path → path` 回落：**已移入回收目录的片段仍能补复核** |
| `run_batch(db, limit, progress, log, stop_event, batch_id, scope)` | 批量入口。`enabled=False` 时**返回 `error` 而不抛异常**（一键执行据此转成阶段级失败） |
| `extract_wav(video_path, vid)` | 抽 16 kHz 单声道 PCM 到 `work_dir/audio/{id}.wav`（归档取的就是这个文件） |
| `review_wav(wav, duration_sec)` | VAD + ASR；产出 `speech_present` / `speech_ratio` / `speech_segments` / 转写 |
| `judge(transcript, row)` | 本地 LLM（ollama OpenAI 兼容接口）判有用性。结论**只作参考元数据**，不作硬筛选条件 |
| `check_ready()` | 返回未就绪原因列表（缺依赖 / 缺模型） |
| `_effective_chars(text)` | 去空白与标点后的有效字数 —— `min_transcript_chars` 那道噪声闸的判据 |

**`speech_present` 的判据**：VAD 语音占比 ≥ `vad_speech_threshold`，**或** ASR 转写有效字数 ≥
`min_transcript_chars`（VAD 漏检时的兜底）。**环境音（脚步 / 开门 / 犬吠 / 孩子哭）不算** ——
它们没有"语音"。这是口径，不是缺陷。

## `archiver.py` —— L2.7 语音档案

| API | 说明 |
|---|---|
| `archive_pending(db, cfg, limit, progress, log, stop_event)` | 批量入口，走 `db.archive_queue()` |
| `archive_one(cfg, row, adir, ts)` | 复制 `{id}.wav` + 转写 txt 到 `archive.dir/<年>/`，追加写 `manifest.jsonl`（幂等第二依据）。**无缓存 wav 的行返回 `skipped`** |
| `check_ready(cfg)` / `check_warnings(cfg)` | 硬错误（拦截按钮） / 风险提示（`st.warning`，不禁用） |
| `safe_stem(row)` | 产物文件名（含来源 id 后缀，避免撞名） |
| `same_drive(p1, p2)` / `is_drive_root(p)` / `same_drive_warnings(...)` | 同盘 / 盘根判定。**同一套口径被 `highlighter`、`compile_period` 复用** |
| `archive_dir_of(cfg)` / `wav_cache_dir(cfg)` / `cached_wav(cfg, id)` | 路径解析 |

**归档门 = `speech_present=1`**，即"音频复核确认为有效语音的处置候选"。这就是"保留所有**可用**音频"的实现
（完整复核见 `_archive/结论-音频归档口径复核.md`）。

## `highlighter.py` —— L2.8 画面精华

| API | 说明 |
|---|---|
| `HighlightCutter.cut_one(row, hdir, ts, log=None)` | 单条：抽帧（CLAHE 增强）→ 帧差预筛 → 粗扫 → 候选窗 → 精扫 → 合并 → 聚合 → 重编码切片 |
| `HighlightCutter.run_batch(db, limit, ..., rehighlight=False, only_dropped=True)` | 批量入口。`rehighlight=True` 走重剪队列；剪完按 `auto_dispose` 自动处置（`_dispose_one`） |
| `merge_events(hits, duration, gap_merge, min_duration, pre_pad, post_pad, max_clips, grade_a_seconds, grade_a_persons)` | 把离散"有检帧"聚合成有意义的事件并分级 |
| `build_windows(hits, duration, gap, pad)` | 粗扫命中 → 精扫候选窗 |
| `merge_two_levels(c_hits, f_hits, scanned, fine_on, keep_coarse_suspect=True)` | 两级合并。**`keep_coarse_suspect=True` 时"粗扫看到、精扫没确认"的信号降级保留为 C 级，不再丢弃** |
| `parse_shot_time(stem)` | 从文件名时间戳解拍摄时刻 —— 周期合辑能按周/按月分组的**前提资产** |
| `probe_av(path, ffprobe)` | 读源片的分辨率/帧率/像素格式/采样率/声道（切割与拼接都依赖它） |
| `check_ready(cfg)` / `check_warnings(cfg)` / `highlight_dir_of(cfg)` | 同上口径 |

**产物分级**：`A_确认`（精扫确认 ≥ `grade_a_seconds` 或多人）/ `B_短暂` / `C_疑似`（粗扫看到过或纯动静）。
三者都切 mp4（`c_cut_mp4`），C 级另留代表帧。**C 级是档案，不进人工审核队列。**

**为什么必须重编码**：监控 GOP 长，`-c copy` 会把切点吸附到关键帧。

## `mover.py` —— 处置层（唯一写文件的地方）

| API | 说明 |
|---|---|
| `move_one(db, row, cfg, tier, log, clips, state)` | 单条移动。**不传 `state` 时必须回库取新鲜行**：调用方给的常是剪辑前快照（`highlight_at` 还是 NULL），拿它判会把"刚剪完只有 C 级"误放进 `待保全` |
| `move_rows(db, rows, cfg, log, limit)` / `move_all(db, rows, cfg, log)` | 批量。`limit` 来自 `runtime.batch_size_limit`（护栏） |
| `align_one(...)` / `align_subdirs(db, cfg, log, limit, verify=True)` | 把回收目录里的存量对齐到正确子档。**幂等**；先拿行内判断与队列口径对一遍，不一致就跳过并报错（宁可停下也不照着错的状态搬文件） |
| `undo_move(db, row, log)` / `undo_batch(db, rows, log)` | 撤销：按 `action_log` 搬回，并清 `trash_path`/`trash_tier` |
| `recycle_state(row, clips, verify, pending_ids)` | **保全状态三态的唯一判据**（clipped / pending / plain） |
| `is_pending(row, clips, pending_ids)` | 「待保全」判据（两条队列 ∪ 硬失败行）。⚠️ 只在回收目录语境用 |
| `has_ab_clip(clips, verify=True)` | 「已剪辑」判据：现算 clips 且产物 mp4 **此刻仍在**。`verify=False` 给 UI 现状统计用（不碰文件系统） |
| `decide_tier(row, cfg)` | 分档：存在未达阈值的疑似目标 ⇒ 降为低置信 `B`（漏检高发区不进可批量删除档） |
| `release_params(cfg)` | 放行门槛 + 「必须无人物信号」开关 —— 一键执行与审核台共用，避免两处口径漂移 |
| `trash_target_path(trash_root, tier, row, subdir)` / `current_subdir(trash_path, trash_root)` | 路径构造与反解。**保留原目录结构**杜绝重名覆盖 |
| `write_reports(db, cfg, batch_id)` / `recycle_stats(db, cfg, verify=False)` | 清单 CSV + 空间统计 / 三态现状 |

## `jobs.py` —— 后台任务与编排

| API | 说明 |
|---|---|
| `Job` | 状态机 + 进度 + 速度 / ETA + 日志环形缓冲 + `request_stop()` |
| `JobManager.start(kind, target)` | 防重复启动；`_keep_awake()` 申请 `ES_CONTINUOUS\|ES_SYSTEM_REQUIRED` 防休眠，`finally` 释放（**刻意不加 `ES_DISPLAY_REQUIRED`**，否则屏幕常亮） |
| `start_scan` / `start_analyze` / `start_audio_review` / `start_archive` / `start_highlight` / `start_rehighlight` | 单阶段启动 |

| `_run_pipeline(job, db, cfg, opts)` / `start_pipeline(db, cfg, opts)` | 一键执行（七阶段，见 [`架构设计.md`](架构设计.md) 第三节） |
| `pipeline_precheck(cfg, opts)` | 跑前体检：把各阶段的 `check_ready` 汇总成人话 |
| `count_rehighlight_pending(db, cfg, only_dropped)` | 按钮上的显示依据（版本取自 config，而非硬编码） |

## `ui.py` —— Streamlit 工作台

六个页签（顺序即默认展示顺序）：

| 页签 | 入口 |
|---|---|
| **审核工作台** | `tab_review` —— 缩略图 + 判定依据链 + 快捷键；顶部有一键放行「无人」候选 |
| **批量浏览** | `tab_grid` —— 九宫格分页多选，批量移动后自动出清单 CSV 与空间统计 |
| **精华复核** | `tab_highlight` —— 翻 A/B 产物（C 级是档案）；回收目录三堆卡 |
| **执行进度** | `tab_progress` —— 后台任务实时面板 + 批次进度 + 吞吐 / ETA |
| **误判分析** | `tab_feedback` —— 误判原因分布与调参建议 |
| **设置与扫描** | `tab_settings` —— 路径与参数、⚡ 一键执行、分步执行、回收目录三堆归位 |

辅助：`render_reasons()` 判定依据链、`job_panel()` 任务面板、`hotkeys.install()` 注入快捷键、
`_queue_*()` 审核队列分页与定位（谓词全部来自 `db`，UI 不自己拼 SQL）。
**改完 UI 要跑真渲染冒烟** `scripts/smoke_ui.py` —— 源码级字符串断言只能证明"函数被调用了"。

## `cli.py` —— 命令行入口

```bash
./.venv/Scripts/python.exe -m src.cli scan    --root D:/监控/2024 --limit 500
./.venv/Scripts/python.exe -m src.cli analyze --limit 500
./.venv/Scripts/python.exe -m src.cli stats

```

## `hotkeys.py`

`install(keys)` 注入 JS：**按按钮文案定位**，所以改按钮文案必须同步改键位表里的文案
（`selftest` 有"键位 × 按钮文案一致性"断言，防改文案后快捷键静默失效）。
`hint_markdown()` 生成页面上的快捷键提示。
