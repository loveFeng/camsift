# 配置参考

> **状态：现行** ｜ 参数真源 = **`config.json`（实际生效）** + `src/config.py` 的 `DEFAULT_CONFIG`（缺项补齐）。
> 两者不一致时**永远以 `config.json` 为准**；`DEFAULT_CONFIG` 只决定"没写这个键时的初值"。
> 改参数后在 UI 上要**先点「保存设置」再启动任务**，否则跑的还是旧配置。

---

## 一、加载规则

1. 启动读 `config.json` → 与 `DEFAULT_CONFIG` **深合并**（只合并 dict，其余直接覆盖）。
   ⇒ **增删配置项不会让旧配置失效**，老 `config.json` 缺的键自动补上默认值。
2. 文件损坏（0 字节 / 半截 JSON）→ 按 `config.json.bak` → `*Conflict*.json` → 默认 的顺序恢复，
   损坏件留档为 `config.json.corrupt-<时间戳>`，并通过 `LAST_NOTICE` 在 UI 顶部告警。
3. 保存是**原子写**（临时文件 + `fsync` + `os.replace`），成功后 `.bak` 才更新。

> ⚠️ **已知的默认值漂移**（在办，见 [`待办与风险.md`](待办与风险.md)）：
> `DEFAULT_CONFIG` 里 `archive.dir` / `highlight.dir` 写的是 `E:\...`，而现网 `config.json` 用的是
> `G:\change\...`。**看代码会得到错误的路径印象** —— 判断路径一律以 `config.json` 为准。

## 二、路径四件套（顶层键）

| 键 | 现网值（示例） | 约束 |
|---|---|---|
| `source_root` | `G:\change\2016` | 视频源根目录，**程序只读** |
| `trash_root` | `G:\need-del` | 分级回收目录。**必须与 `source_root` 同盘**，否则 `move` 退化成复制 |
| `work_dir` | `E:\video-search\data` | 本地 SSD 工作目录（音频缓存等）。**绝不能落在移动硬盘上** |
| `runtime.sqlite_path` | `E:\code\video-search\data\videos.db` | 数据库位置 |

**产物的两条红线**：`archive.dir` 与 `highlight.dir` **绝不能设在 `source_root` / `trash_root` 所在的盘**
（那里会被手动清空）。代码注释里写着这条红线，但**现网配置恰好把两者都放在了 `G:`** —— 见 `待办与风险.md`。

## 三、元数据与分析（`analysis`）

| 键 | 默认 | 作用 |
|---|---|---|
| `sample_frames` | 6 | 每个片段抽帧数（L1 是**稀疏采样**，这正是需要 L2.8 高密度复核的原因） |
| `grid_cols` / `thumb_width` | 3 / 320 | 缩略图网格列数 / 单帧宽度 |
| `decode_backend` | `auto` | `auto` / `cuda` / `cpu` |
| `yolo_enabled` | true | 没模型文件时自动降级为纯动静检测 |
| `yolo_model_path` | `data/models/yolov8n.onnx` | 换生产模型改这里。**新增规格必须先过两道门**（装载门 / 尺寸门），工具 `scripts/download_model.py` |
| `yolo_conf_threshold` | 0.50 | 判定阈值 |
| `yolo_keep_raw_above` | 0.15 | 低于此值不记录；**高于它的"未达阈值检出"会留证** —— 误判归因的前提 |
| `yolo_input_size` / `nms_threshold` | 640 / 0.45 | |

## 四、打分（`scoring`）

| 键 | 默认 | 说明 |
|---|---|---|
| `person_weight` | 50 | **人物权重最高** —— 检出即保底，这是"宁可多留"的量化形式 |
| `vehicle_weight` / `animal_weight` | 40 / 15 | 车辆 / 动物 |
| `motion_area_weight` / `motion_area_threshold` | 10 / 0.05 | 前景面积占比超阈值才加分 |
| `audio_weight` | 10 | 有声音加分 |
| `audio_db_threshold` | -50.0 | `volumedetect` 的 `mean_volume`（dB）阈值：实测"环境底噪 vs 确实有动静"的分界 |

> 现网 `config.json` 里残留一个已废弃键 `scoring.audio_energy_threshold`（旧 RMS 口径，与新 dB 口径对不上）。
> 无害（无代码读它），下次保存设置时会自然消失。

## 五、结论与放行（`verdict`）

```text
score <= trash_threshold(0)     → 建议清理（trash，进 A/B 回收档）
score <  review_threshold(30)   → 需人工确认（review）
score >= review_threshold(30)   → 建议保留（keep）
```

| 键 | 默认 | 说明 |
|---|---|---|
| `release_threshold` | 30 | 批量放行的分数上界，**只作保险丝**（30 等于不生效：review 档本就 <30）。设 0 并关掉语义条件，即退回最早的"仅 0 分桶" |
| `release_require_no_person` | true | **真正决定放不放行的是它**：必须"无人物信号"（未检出人物，且 `decision_trace` 里也没有"疑似人物未达阈值"）。见 ADR 0003 |

## 六、类别（`classes`）

`person` / `vehicle` / `animal` 三组把 COCO 类名映射到打分权重。`classes.vehicle` 不含
`airplane`/`boat` 等与家庭监控无关的类。

## 七、L2.5 音频复核（`audio`）

| 键 | 默认 | 说明 |
|---|---|---|
| `enabled` | false | 总开关（引擎装好后再开） |
| `engine` | `funasr` | `funasr`（阿里，默认）/ `faster_whisper`（降级兜底） |
| `device` | `auto` | `auto` = 有 CUDA 用 GPU 否则 CPU。GPU 被其它任务占满 / 驱动重置时改 `cpu` 保复核不饿死 |
| `model_dir` | `data/models/audio` | fsmn-vad / paraformer 模型目录 |
| `whisper_model` / `language` | `small` / `zh` | 降级引擎的规格与语言 |
| `sample_seconds` | 0 | `0` = 抽全量音轨；`>0` 只抽前 N 秒（快速初筛） |
| `vad_speech_threshold` | 0.3 | 语音占比低于此值 → "基本无人声" |
| `min_speech_sec` | 1.0 | 单段人声短于此视为噪音段，不转写 |
| `vad_speech_noise_thres` | 0.6 | fsmn-vad 语音/噪声判别阈值（越高越宽容） |
| `min_transcript_chars` | 4 | **VAD 漏检时 ASR 兜底**：有效字数 ≥ 此值判有语音。它也是把"嗯/啊/哦"这类 ASR 幻觉碎片挡在门外的闸 |
| `dsp_filter` | `highpass=120,lowpass=3400,afftdn=nr=12:nf=-25` | 三级流水线第 2 级：VAD 漏检时生成降噪副本再 VAD。置空 `""` 关闭第 2 级 |
| `punc_model` | true | 启用标点模型 `ct-punc`（让人好读） |
| `max_segments` | 40 | 单片段最多转写段数（控成本） |
| `cleanup_wav` | false | 复核落库后是否清 wav。**保持 false** —— 归档与页面回看都吃这个缓存 |
| `review_scope` | `all` | `all` = 待清理 + 需人工确认 / `trash` / `review` |

> `enabled=False` 时 `run_batch` **返回 `error` 而不抛异常**，一键执行据此把它转成阶段级失败。

## 九、L2.8 画面精华（`highlight`）

### 9.1 两级检测

| 键 | 默认 | 说明 |
|---|---|---|
| `coarse_fps` / `coarse_size` / `coarse_conf` | 3.0 / 640 / 0.15 | 粗扫全片：**低阈值只管不漏**（误检交给精扫过滤），密度是 L1 的若干倍 |
| `fine_enabled` | true | 关掉即退化为单级粗扫 |
| `fine_fps` / `fine_size` / `fine_conf` | 4.0 / 1280 / 0.25 | 精扫候选窗：**高分辨率负责看清**，`fine_conf` 就是 A/B 级的"确认"门槛 |
| `fine_window_pad` / `max_fine_ratio` | 2.0 / 1.5 | 候选窗两侧扩展秒数 / 精扫帧数上限（相对粗扫），超出只对高分窗精扫 |

**为什么两级**：L1 每段只抽十几帧（占比极小），小孩身形小、进出快、或被门框挡住只剩半身，这种密度必然漏；
但全片拉到 1280 精扫是十几小时量级，不现实。所以"粗扫负责不漏、精扫负责看清"。

### 9.2 分级产出

| 键 | 默认 | 说明 |
|---|---|---|
| `suspect_conf` | 0.15 | 低于 `fine_conf` 但高于此值 → C 级疑似 |
| `grade_a_seconds` / `grade_a_persons` | 8.0 / 2 | A / B 级的时长分界；多人同框直接算 A |
| `keep_person` / `keep_vehicle` / `keep_animal` | true / false / false | 哪类目标算精华（门口过车一般无保留价值） |
| `motion_fallback` / `motion_fallback_threshold` | true / 0.05 | 无人但有大幅动静（开关门 / 物品倒地）→ 归入 C 级 |
| `thumb_per_clip` / `thumb_width` | 1 / 640 | 每段代表帧数 / 宽度（C 级时这张图就是产物，别太小） |

### 9.3 删前保全（Track C · ADR 0006）—— 本次保全量的主控

| 键 | 默认 | 说明 |
|---|---|---|
| **`version`** | **`hlv3`** | 产物口径版本。**改它必须同步 `highlighter.HL_VERSION` 与 `db.HIGHLIGHT_TARGET_VERSION`**（`selftest` 有断言钉住三者相等，漂移会让回收目录永远归不了零） |
| `keep_coarse_suspect` | true | 粗扫看到、精扫没确认 ⇒ **降级保留为 C**（不再丢弃）。关掉即回到旧行为：这类信号直接消失 —— 那是"474 条视频删后一个字都不留"的成因 |
| `c_cut_mp4` | true | C 级也切可播放 mp4（关掉则只留代表帧） |
| `c_thumbs` | 3 | C 级每段代表帧数 |

### 9.4 预处理与聚合

| 键 | 默认 | 说明 |
|---|---|---|
| `clahe` | true | 红外 / 夜视对比度增强（素材绝大多数是夜间，必开） |
| `motion_prefilter` / `motion_threshold` / `prefilter_dilate` | true / 0.004 / 1 | 帧差预筛：静态画面不送检测（省算力），阈值刻意调低宁可多检；窗口向两侧扩展采样帧数补回入场/出场 |
| `gap_merge` / `min_duration` | 3.0 / 1.0 | 有检帧间隔小于 `gap_merge` 合并为同一事件；短于 `min_duration` 的事件丢弃（已去掉旧口径的"整段丢弃"行为，见 ADR 0006） |
| `pre_pad` / `post_pad` | 2.0 / 3.0 | 事件前后留白（避免人物"半路冒出来"、动作收尾完整） |
| `max_clips_per_video` | 8 | 单视频最多切几段（按价值排序，防输出失控） |

### 9.5 编码

| 键 | 默认 | 说明 |
|---|---|---|
| `crf` / `preset` | 20 / `veryfast` | 必须重编码，**不能 `-c copy`**（监控 GOP 长，copy 会把切点吸附到关键帧） |
| `audio_bitrate` | `128k` | 产物音轨码率 |
| `gop_seconds` | 2 | 输出关键帧间隔（便于拖动预览） |

### 9.6 审核减负（ADR 0001）

| 键 | 默认 | 说明 |
|---|---|---|
| `keep_full_ratio` | 0.6 | 精华占比超过此值 ⇒ 整片都有内容，切片反而丢上下文 ⇒ **自动改判保留原片** |
| `auto_dispose` | true | 剪辑完成后是否自动处置未决候选：`keep_full` → 保留；其余（含无精华）→ 移入回收目录。关闭则只剪不移 |

## 十一、一键执行（`pipeline`）

| 键 | 默认 | 说明 |
|---|---|---|
| `stages.{scan,analyze,audio,archive,release,highlight,align}` | 全 true | 七个阶段可单独勾掉（align=回收目录三堆对齐） |
| `stage_limit` | 100000 | 下游各阶段的单次处理上限。按 ADR 0004，**只有扫描按"本次上限"分批**，其余阶段一律跑全库队列（带幂等标记）—— 这个值只是防跑飞的天花板 |

（UI 上另有 `scan_with_audio` 复选框：扫描时是否顺带算音轨能量。）
