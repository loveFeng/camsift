# 队列的跳转与筛选：三处共用同一组谓词

---
status: accepted
date: 2026-09-10
---

放行落地后待审核从 1265 降到 342，但审核台和批量浏览只能「上一条 / 下一条」、
「上一页 / 下一页」地翻 —— 342 条是 4 页审核台、15 页九宫格。问题从"条目太多"
变成了"在这几百条里怎么定位"：想看分数最高那几条，得从第 1 页点到最后 1 页。
决定：审核台加「跳到第 N 条」「跳到分数 ≥X」，批量浏览加页码跳转 + 首页/末页；
两页共用同一个筛选条（仅看检出人物 / 仅看检出人声 / 最低分 ≥X）。

## 三处谓词必须逐字一致

队列、计数、跳转定位是同一个筛选条件下的三个视图，任何一处单独拼 SQL 都会分叉：

| 视图 | 方法 | 分叉后的症状 |
|---|---|---|
| 分页取数 | `review_queue(**filt)` | 筛选后仍在查全量 |
| 显示总数 | `count_review_queue(**filt)` | "显示 300 条，翻到第 2 页却是空的" |
| 跳转定位 | `count_review_below(x, **filt)` | 跳过去的分数段与页面上说的对不上 |

`count_audio_pending` 就这样错过一次：计数只看"未处置"，队列放宽到"处置候选"，
结果**报 0 而实际 2322**，任务进度条的分母跟着错。所以这一轮把谓词收进
`Database._review_sql()` 一处，三个方法都从它拼 WHERE。

## 「跳到分数 ≥X」= 数出低于 X 的条数

队列本身按 `COALESCE(final_score, retention_score, 0) ASC` 排，所以：

```
第一条分数 ≥ X 的位置  ==  分数 < X 的条数
```

用一条 `COUNT(*)` 就能定位，不需要把队列拉进内存扫一遍，也不需要引入游标分页。
`count_review_below` 不是"给 UI 用的辅助函数"，它是队列排序契约的推论 ——
排序方式一变（比如改成按时间倒序），它必须跟着重写。

## 当前这批数据里「仅看检出人物」是空筛

实测 342 条待审核**全部** `has_person=1`，且**没有一条分数 ≥30**：

| 分数段 | 条数 | 说明 |
|---|---|---|
| 12.5–20 | 105 | 人物刚过检出下限（人物权重 50 × 检出下限 0.25 = 12.5） |
| 20–30 | 237 | 人物 + 画面动静叠加，仍未到保留线 |

也就是说：无人片段已被 ADR 0003 的批量放行清完，剩下的全是"看到人但分数不高"。
这解释了为什么放行门槛 30 只管住了 0 条 —— 它是保险丝，不是主闸。
保留「仅看检出人物」开关不是为了现在有用，而是下一次扫描进来新素材时，
无人片段会重新混进队列，这个筛子立刻生效。

## Considered options

- **只在审核台加号输入、不加分数跳转** —— 否掉：队列的**主排序维度就是分数**，
  "跳到第 N 条"要求人先知道 N 是多少；而"我想看 25 分以上的"是直接可表达的意图。
- **把整条队列一次拉进 session_state，本地切片翻页** —— 否掉：全库待审核上到几千条时，
  每次 rerun 都把几万个 id 塞进 session_state，内存和时间都白花；现在的分页
  只加载当前页 100 条，跳转也只加载目标页。
- **给跳转做位置补偿（记住"某条现在挪到哪了"）** —— 否掉：队列是活视图，
  处置/放行/重新分析都会让条目进出，位置本就会漂。补偿要维护一份影子索引，
  复杂度换来的只是"看起来没动"。跳过去看到的就是那一刻库里的真实顺序。
- **批量浏览与审核台各写一套筛选控件** —— 否掉：两页看到的条目必须同一口径，
  否则"批量浏览里选了 24 个、审核台里找不到"。

## Consequences

- **筛选条件换掉后必须回到第一条**（`_q_sig` 指纹比对），否则会停在编号已经
  不存在的旧位置上 —— 表现为"换了筛子页面却空着"，看起来像 bug。
- **越界跳转一律夹住**：条号 > 总数跳到末尾；页码 > 总页数收到末页。
  输入框不设 `max_value`（筛选一变总数就变，Streamlit 会因 session 里的旧值越界报错）。
- **"跳到分数 ≥X"在无人达标时给出明确提示**，不静默把人丢到末尾 ——
  当前 342 条全部 <30，输入 30 就会走到这条分支。
- **审核台的空态必须先于筛选条渲染判断**，且空态文案要区分"本来就没有待审核"与
  "被筛选条件挡住了" —— 否则筛子把队列清空后，界面上没有入口把筛子摘掉。
- **`_queue_load` / `_queue_step` / `_queue_jump` 都改为接收筛选字典**，
  新增队列维度时只改 `_queue_filters()` 与 `Database._review_sql()` 两处。
