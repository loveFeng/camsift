# 程序全驱动、人工只做抽查：L1 改判据、审核台退役、删除权永远在人手里

---
status: accepted
date: 2026-10-05
---

机主对 v3 的要求：**"尽量人类少审核，只靠程序驱动，人类只需要可以有抽查的页面随机选择
查看一下即可。然后就是最后的删除是人类手动删除，程序不做任何删除，只创建和移动。"**

这是对 ADR 0001（「先剪后删取代人工审核」）的**推进而非推翻**：0001 说的是"不用人逐条
看"，本 ADR 说的是"连'人挑出可疑的'这一步也去掉，改成抽 N 条验机器"。红线不变 ——
**程序永不删除**，本 ADR 也增加一条：程序永不代替人做最终处置的**记账归属**。

## 决定

### 1. 人工审核台退役，改成抽查页

`tab_review` 从"逐条过处置"重做为"抽 N 条看机器判得对不对"，两个入口：

| 入口 | 抽样源 | 验的是什么 |
|---|---|---|
| 🎯 L1 判定结果 | 跨 verdict 分层 `trash:review:keep = 4:3:3` | L1 判得准不准 |
| ✂️ 已剪 A/B 精华 | 按**片段**抽（`sample_ab_clips`） | 剪辑挑得对不对 |

三个关键选择：

- **trash 层配额加倍（4/10）**：那批已被机器处置，误判的代价最大（漏保）。
- **精华按片段抽不按视频抽**：一视频剪出 5 段的话，按视频抽会让"剪得最多的那条"
  占满样本，而那正是机器最自信的部分 —— 抽样就失去意义了。
- **固定随机种子可复现，「换一批」= seed+1 不是随机数**：抽查的两个核心用途是
  "对齐口径"（多个人看同一批）和"复查某条"，两者都要求同一批能重抽出来。
  用 `ORDER BY random()` 一次就废掉这条。

### 2. 抽查可「即改判」，且「该留」会真的把原片搬回

四个动作：判对了 / 该留 / 该删 / 记为误判。

**「该留」走 `mover.undo_move`，原片搬回源目录。** 旧审核台的"误判保留"只写
`human_decision='keep'` 而**不搬文件** —— 原片继续躺在回收目录里，机主后来清空
回收目录时它跟着一起没了。这是最隐蔽的一种丢失：看起来"判为保留了"，实际东西早没了。

片段级改级（`db.set_clip_grade`）必须同步派生列（`highlight_best_grade` /
`ab_clips_count`）并重跑 `mover.align_one()` —— 否则原片从「已剪辑」落进顶层档位，
**机主以为可删、实际 A 级 mp4 还在硬盘上**。

### 3. L1 判定从「检出强度分」改为「质量分」

旧公式 `score = 50 × 单帧最高 conf`，阈值 30 ⇒ **conf ≥ 0.6 直接 keep**。
而检测阈值是 `yolo_conf_threshold=0.4` ⇒ **`[0.40, 0.60)` 这条 0.22 宽的带子里
所有真人全部误判 keep**，永不进任何队列、永不剪辑 —— `highlighter` 存在的意义
（8 倍采样密度重扫）被 L1 的判定废掉了。

v2 三步：

```
Step1 多帧一致性  b_persist = 0.6 + 0.4×min(1, persist/0.4)   永不为 0
                  b_size    = 0.5 + 0.5×min(1, area_med/ref)  中位数抗单帧大框
Step2 内容分      content = 100×(1 − Π(1−c_i)×…)              noisy-OR 饱和聚合
                  c_person = 0.55×conf_med×b_persist×b_size
Step3 质量乘数    penalty = min(45, 25糊+20暗+10灰+15低分辨率+10远小+10单帧)
                  score = content × (0.5 + 0.5×(100−penalty)/100)
```

- **乘数不是减法**：减法会让 `max(0, 小内容−大扣分)=0` 直接落 trash = "质量差否决
  内容"，语义错误。乘数最低 5 折、永不清零。
- **noisy-OR 不是裸加法**：裸加法可无限累加（三个弱信号刷满），noisy-OR 天然饱和、
  逐项可解释、天然落在 0–100。
- **阈值必须随公式一起换**：`trash_threshold=0` 是为旧的 125 分制加法设计的。
  v2 是 0–100 质量分，继续用 0 则 trash 几乎不可达。起点值
  **trash 20 / review 35**，`load_config` 检测"用 v2 但阈值没换"并告警。
  阈值**暴露成设置页控件** —— 它是最需要按素材微调的参数，让机主手改 JSON 不现实。

### 4. 保底规则 F0：任何一帧检出人，就不判 trash

写死在代码里、**不提供配置关掉**（底线语义不该被一个配置项关掉）。
理由只有一句：**"看到了人"就不该判"这里没有价值"**。

它来自跑算例时发现的一个真缺陷：原设计的 veto 条件
`is_blurry and is_tiny_person` 取消了弱保底 F4/F5，**而"糊 + 远小"恰恰是最需要
保底的场景** —— 糊画面里的小目标更可能是真人。veto 逻辑写反了。

### 5. 处置留痕：`decided_by` 区分谁做的决定

`human_decision` 扩容成"机器处置记录"，若无 `decided_by` 列，抽查时无法区分
"人判的"和"机器判的" —— **而这恰好是抽查的核心目的**。这一列必须在第一批数据
被自动处置**之前**加上（历史行可事后判定时回填，未知的留 NULL 表示"历史数据"）。

`set_machine_decision` 是**独立方法**而非默认参数 —— 省略 `by="auto"` 要一眼可见。
`move_one`/`align_one` 默认 `auto`、`undo_move` 默认 `human`，**两者故意相反**：
各自那条路径上"多数调用"是谁就取谁。唯一机器调用点（`_dispose_one` 的捞回）
显式传 `by="auto"`。

同事务内补记 `decide:*` 日志（本项目未开 WAL，另开连接写 `action_log` 在剪辑
循环里会间歇 `database is locked`）。

### 6. 删除 tab_grid 与 hotkeys（性能与正确性，不只是简化）

- `st.tabs` **每次 rerun 都执行所有 tab 的代码**。`tab_grid` 一次渲染 24 缩略图
  + 72 个按钮，纯属白付。
- `hotkeys.py` 按**按钮文案**子串匹配定位目标，Streamlit 全 tab 渲染导致
  **在任意页按空格都会去点审核台的处置按钮**，且失效是**静默的**（三层降级都
  成功时才提示）。

`ui.py` 1993 → 约 1500 行，页签 6 → 5。

## Considered options

- **保留审核台当"逃生舱"，只新增抽查页** —— 否掉：`st.tabs` 会执行所有 tab 代码，
  留着就等于每次 rerun 都付它的渲染成本，而逃生舱的实际使用率会趋近于零
  （既然抽查能改判，逃生舱没有使用场景）。
- **保留快捷键但改用 Streamlit 原生 `st.keyboard_listener`** —— 否掉：抽查页是
  随机抽样，键盘加速的价值消失，而跨 tab 误触的风险仍在。
- **L1 只加质量扣分，不做多帧一致性** —— 否掉：实测旧公式下
  **同一 conf 检出 1 帧与 8 帧同分**，而"单帧闪烁的杂物"和"多帧移动的真人"
  正是靠帧数区分的。只加质量扣分会保留"远小但清晰 = 误判 keep"这个洞。
- **直接抬 `yolo_conf_threshold`** —— 否掉：会把只在少数帧出现的真人一并干掉
  （与 ADR 0006 第 5 条同源论证）。
- **抽样用 `ORDER BY random()`** —— 否掉：无种子、rerun 就换一批、无法复现，
  且 3 万行全表排序。
- **删除 `final_score` 写入（计划原写）** —— **撤销**。它与 `retention_score`
  恒等，但它是**对外的判定结果** —— 12 处 SQL 写
  `COALESCE(final_score, retention_score, 0)`，selftest 也直接 SELECT 它。
  "两值相等"≠"冗余"：一个是内部量、一个是对外契约。

## Consequences

- **人工的工作形态变了**：从"逐条过"变成"抽 10 条看 2 分钟"。抽查的价值完全取决于
  样本是否随机可复现 —— 种子必须显示、可回填，否则无法与下一个人对齐口径。
- **「改判」必须留痕**：`decided_by='human'` 是"人推翻过机器"的唯一证据。
  抽查页的四个动作都写这一列。
- **自检与冒烟不再依赖真实库**（顺带修掉的设计缺陷）：`selftest` / `smoke_ui`
  原本硬连项目真实库，库不存在时**整个自检在第一处就崩**（此前报"293 项"其实是
  跑到第 189 项就断了，真实 428 项）。给 `ui.main()` 加
  `VIDEO_SEARCH_DB_OVERRIDE` 环境变量钩子（`get_db` 是 `@st.cache_resource`，
  `session_state` 注不进去），两个脚本各造临时库。自检从此只依赖代码 ——
  新机首次装也能跑。
- **测试改造不是形式主义**：7 个 FAIL 全是"已退役设施的断言"，不是真 bug。
  `test_hotkey_binding` / `test_grid_select_all` 等被**反向断言**取代
  （钉死"那套全量审核导航不回来" —— 它一旦回来就意味着"人工要逐条过"又回来了）。
- **`_grid_audio_html` 是可复用资产**：它随 `tab_grid` 一起删时差点永久丢失，
  从 git 取回接到抽查页。**删宿主不等于删资产**。
- **本 ADR 不改变**"程序只创建和移动、删除始终由机主手动完成"这条红线。
  `mover` 里没有任何 `os.remove` / `shutil.rmtree` 指向原片。
- **抽查页的音频关口只提示不拦**：与程序路径同口径。程序路径的 `_dispose_one`
  早就撤掉了这道守卫（音频队列已放宽为处置候选，移入回收后仍能补复核）；
  半拦半不拦会让一键执行的终点不可预期。
