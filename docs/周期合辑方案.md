# 周期合辑方案

> **状态：现行（原型已跑通，未转正）** ｜ 实现：`scripts/compile_period.py`（约 400 行）
> 定位：**独立的下游模块**，与 L2.8 画面精华并列而非从属。
> 原始出处见 [`_archive/项目体检与周期合辑可行性.md`](_archive/项目体检与周期合辑可行性.md) §4（含当时的完整实测上下文）。

---

## 一、定位边界：两件事，别混

| 模块 | 职责 | 一句话 |
|---|---|---|
| `src/highlighter.py`（L2.8） | **检索 + 切割** | 找出"哪几秒有价值"，切成一个个 mp4 |
| `scripts/compile_period.py` | **编排 + 拼接** | 把某周 / 某月的片段按时间顺序串成一条片子 |

`highlighter` 不做时间线，编译器不碰检测。所以这**不是**"给精华剪辑加个按钮"，
而是一个独立的**下游模块** —— 项目术语表里 "成片 / 集锦" 被刻意排除在「**画面精华**」之外，
正是为了不让这两件事混成一个概念；本模块的名字是「**周期合辑**」（见 `CONTEXT.md`）。

## 二、实测结果（快照，真实数据、零失败）

| 期号 | 片段 | 时长 | 体积 | 耗时 | 级别构成 |
|---|---|---|---|---|---|
| `2015-12`（月） | 145 | 19.5 分钟 | 183 MB | 138 s | A 58 / B 87 |
| `2016-W04`（周） | 103 | 14.1 分钟 | 114 MB | 109 s | A 44 / B 59 |

产物三件套：`{期号}.mp4` + `{期号}.manifest.json`（每段来源 / 时刻 / 级别 / 置信度）+ `{期号}.节目单.txt`。
成片规格校验：`h264 1280×720 yuv420p` + `aac 48000Hz 单声道`、`+faststart`。

> 数字会随库增长而漂；可编期分布同理。要最新值直接 `--list`。

## 三、设计要点 —— 以及为什么必须这么做

**① 两遍法，不能一条命令拼完。**
一次 `filter_complex` 拼 300+ 段会撞 **Windows 命令行 32K 字符上限**（某期就有 327 段，光路径约 2.6 万字符）。所以：

```
pass 1  逐段归一化转码（分辨率 / 帧率 / 像素格式 / 采样率 / 声道统一，无音轨补静音）
pass 2  concat demuxer + -c copy（秒级完成）
```

附带好处：pass 1 的中间片段可复用，改顺序 / 换片头不必重新解码源片。

**② 必须归一化三个维度，不能赌"参数一致"。**
当前产物恰好全同规格、`-c copy` 能直接拼，但那是**单一机位 + 单一 DVR 编码**的运气：
分辨率/像素格式不同 → 拼接直接失败；帧率不同 → 时长漂移、音画不同步；采样率/声道不同 → 音频拼接失败。
归一化后这些变成被保证的约束，而不是"应该没问题"。

**③ 无音轨必须补静音。**
`highlighter._cut` 对无音轨源加 `-an`。若成片里同时有"有音轨段"和"无音轨段"，
concat 会因**流数量不一致**失败。现在源全都有音轨所以不会暴露 —— 但换个机位或某段源没音轨，就会迎面撞上。

**④ C 级默认不纳入。**
C 级里绝大多数是**纯动静**（只有帧差没有目标），拼进去就是一串莫名其妙的画面抖动。默认只取 A/B（`--grades A,B`）。

**⑤ 必须用 `shot_at`，不能用 `mtime`。**
`mtime` 是拷贝时间，`shot_at` 才是拍摄时刻（`highlighter.parse_shot_time` 从文件名时间戳解析）。
**这是这套流水线最被低估的一笔资产** —— 绝大多数家庭影像整理工具就是死在"不知道这段是什么时候拍的"。

**⑥ 跨年周要按 ISO 定义。**
`2015-W53` 与 `2016-W01` 已正确分开。若按"日历周"粗暴切，12 月底到 1 月初那一周会被劈成两半，成片出现断点。

**⑦ 单段时长上限（默认 20 s）。**
一条几十秒的长段会独占成片 —— 而它本身就是 `highlighter.keep_full_ratio` 会改判"整片保留"的那类。默认把它排除在合辑之外。

## 四、用法

```bash
cd E:/code/video-search

# 看有哪些期可编
./.venv/Scripts/python.exe scripts/compile_period.py --list
./.venv/Scripts/python.exe scripts/compile_period.py --by week --list

# 只算计划不产出
./.venv/Scripts/python.exe scripts/compile_period.py --by month --plan

# 出一期（默认输出 work_dir/compilations）
./.venv/Scripts/python.exe scripts/compile_period.py --by month --value 2015-12
./.venv/Scripts/python.exe scripts/compile_period.py --by week  --value 2016-W04 --grades A

# 限制每期时长（超过预算按价值取舍）
./.venv/Scripts/python.exe scripts/compile_period.py --by month --value 2016-01 --max-minutes 20
```

| 参数 | 默认 | 说明 |
|---|---|---|
| `--by` | `month` | `month` / `week`（ISO 周） |
| `--value` | 空 = 全部期 | 期号：`2015-12` / `2016-W04` |
| `--grades` | `A,B` | 纳入的级别（C 是噪声档案，默认排除） |
| `--max-minutes` | 0 = 不限 | 每期时长上限，超预算按价值取舍 |
| `--per-clip-cap` | 20 | 单段时长上限（秒），防长段独占 |
| `--crf` / `--preset` | 20 / `veryfast` | 转码参数 |
| `--out` | `work_dir/compilations` | 输出目录 |
| `--plan` / `--list` | — | 干跑 / 只列期 |
| `--force` | 否 | 已存在也重编 |
| `--cleanup` | 否 | 成片成功后清掉 `_work/` 中间片段 |

**安全边界**：只读源片与数据库；只写 `--out` 下的自创文件；输出目录为盘符根目录时拒绝执行；
与源盘同盘只提示不阻止（沿用项目口径，见 `archiver.same_drive_warnings`）。中间片段默认**保留不删**。
