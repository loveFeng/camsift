# 开发计划：精华检测精度与盲区补检（L1 / L2）

> 缘起：用户问「精华复核，要不要提高一下标准，检测的更仔细一些？」
> 沿用的实证排查（成本 / 覆盖率实测）就在**本文 §1.2 与 §8**，另有当日日志 `.workbuddy/memory/2026-09-10.md`。

## 0. 一页摘要

**结论前置**：不该"全库降阈值 / 加密检测"（那会把椅子杂物当人，与减负相反），
该做的是两件**成本极低**的事：

| 轨 | 做什么 | 解决什么 | 代码量 | 机器成本 |
|---|---|---|---|---|
| **Track 0**（前置） | 把「无精华」拆成"已检测 / 预筛跳过"两个数 | 现在 3,780 条无精华里混着 2,832 条**从没跑过检测**的，数字在撒谎 | 小 | 0 |
| **Track A** | 给 L1 补 CLAHE + 改判据（多帧一致性），并按校准报告定阈值 | L1 的 `has_person` 误报污染了放行判据与处置候选 | 中 | 校准实验 ≈1h |
| **Track B** | 对"整片静止"的盲区补检 K 帧，**检出就留 C 静帧，不再判无精华** | 消除"没看就判无"的逻辑漏洞 | 中 | 全量盲区 ≈30min |

**建议顺序：Track 0 → Track B → Track A。**
理由：Track 0 是量尺（没有它无法证明 A/B 有效）；Track B 成本最低、语义收益最直接；
Track A 牵动"放行/审核"，必须有标注校准把关，不能拍脑袋抬阈值。

**待你拍板两件事**（§10）：
1. 「整片静止」是否等于「无人」？—— 本计划假设**不等于**，要补检。
2. L1 提精度用哪条路？—— 本计划推荐**多帧一致性**，不推荐单纯抬阈值。

**工时**：约 16 小时（≈ 按每周 10 小时节奏 2 周），其中纯代码 ~10h、校准与报告 ~5h、运行观察 ~1h。

## 1. 现状（已逐行核实）

### 1.1 两级链路与**口径不一致**（核心问题）

```
L1  src/analyzer.py::Analyzer.analyze_one   —— 全量，每段 15 帧
      抽帧 640 宽 JPEG(-q:v 3) → cv2.imread → YoloDetector(640, conf=0.4)
      ✗ 无 CLAHE 增强
      判据：任一帧里 person 的最高 conf ≥ yolo_conf_threshold(0.4) ⇒ has_person=1

L2  src/highlighter.py::HighlightCutter     —— 只跑"处置候选"
      coarse: 3fps / width 640  / conf 0.15   ← ✓ 有 CLAHE（_enhance）
      fine  : 4fps / width 1280 / conf 0.25   ← ✓ 有 CLAHE，只跑粗扫命中的窗
      预筛  ：逐帧帧差 ≤ motion_threshold(0.004) 的帧 —— **整帧跳过，不送检测**
```

**两处不一致**：① **L1 没有 CLAHE，L2 有**（`highlighter.py:198-209` 的 `_enhance` 只服务 L2）；
② 分辨率阈值也不同（L1 640/0.4，L2 粗 640/0.15、精 1280/0.25）。
而 L1 的 `has_person` 是**放行判据**（`verdict.release_require_no_person`）与处置候选的来源。

### 1.2 数据基线（2026-09-10 实测，真实库）

| 指标 | 数值 |
|---|---|
| 总视频 | 19,481 |
| 已 L1 分析 | 9,480 |
| 已 L2 剪辑 | 4,825 |
| **无精华** | **3,780（占已剪辑 78%）** |
| 　其中已移入回收目录 | 3,700 |
| 　其中 L1 报过"有人" | 162（conf 0.3×100 / 0.4×49 / 0.5×10 / 0.6×3 —— 全部挤在噪声区） |
| **检测盲区**（`coarse_sent == 0`） | **2,832（占已剪辑 59%，占无精华 75%）** |
| 盲区且判无精华 | 2,832（**100%**，即盲区与无精华高度重合） |
| YOLO 单价（本机 CPU） | 640 = 97ms/帧 ｜ 960 = 211ms ｜ 1280 = 361ms |

> 「盲区 100% 判无精华」正是 §1.1 那条链的必然结果：预筛跳过 → 无 hits → 无 windows → 无 events → 无精华。

### 1.3 三个已定位的具体问题

**P1 —— L1 与 L2 的增强口径不一致（漏 CLAHE）**
低照度素材（本批 L1 自标 `is_low_light`，亮度 41.8、`is_blurry`）下 L1 不增强、L2 增强，
同一素材两级结论不可比。→ Track A 处理。

**P2 —— L1 的 `has_person` 判据是"任一帧最高分"，天然放大误报**
`analyzer.py:219` 取阈值、`247-263` 取 `best`（全部帧展平后的最高 conf）。
只要 15 帧里有**一帧**被椅子/杂物触发（实测低置信区不稳定：同一帧两种抽帧路径像素均差仅
2.4/255，person conf 却能 0 → 0.42 复现），整段就被判"有人"、直接 +50 分。
→ Track A 处理（改为**多帧一致性**，见 §3.2）。

**P3 —— 「无精华」混了两种语义**（"感觉有点多"的真答案）
① 复核过、确实没东西；② **画面帧差没变 ⇒ 一帧都没送检 ⇒ 从未复核**。
分母 3,780 里 2,832（75%）是第 ② 种，且随后**自动移入回收目录**（占比 98%）。
→ Track 0 拆数字 + Track B 补检。

## 2. 目标与非目标

### 2.1 目标

1. **数字诚实**：「无精华」不再包含"从未检测"的片段（Track 0 + Track B）。
2. **压误报不提漏检**：L1 `has_person` 误报率显著下降，**真人漏检增量为 0**（Track A，硬指标）。
3. **减负方向不倒退**：改动后「待审核 / 待放行」计数**不上升**。
4. 所有改动可回归（selftest + smoke_ui + 校准报告），可回滚（配置一键退回）。

### 2.2 非目标（明确不做）

- ✗ **全库降阈值 / 全量加密检测**：成本 14–54 倍（见 §8），且已证伪为"把杂物当人"。
- ✗ 把 VLM（`vlm.enabled`）拉进来补检 —— 它是增强层，且比 YOLO 慢 100–1000 倍。
- ✗ 给视觉链路引入 torch（项目既有约定：视觉链路只走 OpenCV DNN + ONNX）。
- ✗ 改动 A/B 分级规则、放行规则（ADR 0001/0002/0003）、一键执行阶段契约（ADR 0004）。
- ✗ 任何删除类操作（程序永不删除，依旧只 move / 只写标记）。

## 3. 方案总览：三条轨

### 3.1 Track 0 —— 观测口径（前置，必做，~2h）

**为什么先做**：没有这把尺子，Track A/B 的效果无法证明，用户看到的两个数字也无法解释。

- 把 L2 已存在的 `stats['coarse_sent']` 落到 DB：`videos.highlight_sent INTEGER`
  （写入点在 `highlighter.run_one`，stats 组装处 `highlighter.py:530/543`）。
- `db` 新增聚合：`no_clip_stats() -> {"detected": n, "skipped": m}`
  （`highlight_clips='[]' AND COALESCE(highlight_sent,0)>0` / `=0`）。
- UI「精华复核」页把 `无精华 3,780` 拆成 `无精华（已检测）948` + `无精华（预筛跳过）2,832`。
- 历史行回填：一次性从 `manifest.jsonl` 读 `stats.coarse_sent` 回填（脚本，幂等）。
- **验收**：UI 两个数之和 = 原无精华总数；与 manifest 统计一致；smoke_ui 有断言。

### 3.2 Track A —— L1 精度（压误报，~7h）

**A1. 消除增强口径漂移（必做）**
- 把 CLAHE 抽成公共函数（建议 `src/analyzer.py::enhance_clahe(frame, clip, grid)`），
  `highlighter._enhance` 改为调用它 —— **一处实现，两处调用**，杜绝第二次漂移。
- `Analyzer.__init__` 读新配置 `analysis.clahe`（默认 true）、`analysis.clahe_clip`（2.0），
  `analyze_one` 检测循环（`analyzer.py:528-531`）改为 `detect(enhance_clahe(f) ...)`。

**A2. 判据从"任一帧最高分"改为"多帧一致性"（推荐主手段，0 额外算力）**
- `analyze_one` 逐帧统计 `person_frames`（该帧存在 person 且 conf ≥ 阈值 的帧数），
  随 `build_decision(...)` 一起传入。
- `build_decision` 内：`has_person = 1` 需 **`person_frames >= analysis.person_min_frames`**（默认 1 = 现状）。
- 为什么优于单纯抬阈值：真人移动会**连续多帧**命中，杂物误报多为**单帧闪烁**。
  抬阈值会把"只在一两帧里出现、conf 0.3–0.4 的真人"一起干掉；多帧一致性区分的是**稳定性**而非**分数高低**。
- **硬约束**：`person_min_frames > 1` 会减少 `has_person=1` ⇒ 放行集合变大 ⇒ 误放行风险上升。
  所以**必须**先过 A3 校准，且以"真人漏检增量 = 0"为放行条件；否则该参数保持 1。

**A3. 阈值/判据校准实验（`scripts/calibrate_l1.py`，必做）**
- 分层抽样 300 条：① 有精华且 `grade=A/B` 100 条（弱正样本）② 无精华·已检测 100 条
  ③ 盲区+L1 报有人 162 条中取 100 条（重点，已知多为误报）。
- 对每条跑 5 种策略：S0 现状 / S1 抬阈值 0.5 / S2 `person_min_frames≥2` /
  S3 CLAHE+S0 / S4 CLAHE+S2（可选 S5 CLAHE+1280，仅抽 50 条测精度上界）。
- 产出《L1 校准报告》：每组策略的 **误报率 / 漏检率 / 待办计数变化 / 单条成本**。
- 真值获取：复用既有 L1 缩略图拼图（`data/thumbs/{id}_grid.jpg`）+ `scripts/_legacy/probe_crop.py`（一次性脚本，已归档）
  裁框目视；正样本先信"已有 A/B 精华"这一弱标签。
- **验收**：报告给出推荐组合；推荐组合在样本上**误报率降 ≥50% 且漏检增量 = 0**。

**A4. 可重跑（必做，否则 A 只对新素材生效）**
- 3,700 条原片已移入回收目录，`videos.path` 仍是**原路径**（`mover.py` 只写 `trash_path`）
  ⇒ `analyze_one` 的 `path = Path(row["path"])`（`analyzer.py:473`）会"文件不存在"。
- 抽 `_resolve_src(row)`：`path` 不存在时回落 `trash_path`（**照抄 `audioreview.review_one` 的既有做法**，口径要一致）。
- 新增 `db.reanalyze_queue(version)` + 任务入口（`jobs` 新增 `reanalyze` kind 或在 `analyze` 上加 `redo=True`）。
- 幂等标记：新增 `videos.analysis_version TEXT`（写 `"l1v2"`），**不清 `analyzed_at`**。

### 3.3 Track B —— 盲区补检（消"从未检测"，~4h）

**B1. 触发点**（`highlighter.run_one`，判定处 `highlighter.py:550` 与 `621`）
- 现状：`if fine_on and c_hits:` —— 无 hits 直接进"无精华"。
- 新增分支：当 `c_sent == 0`（整片未送检）且 `highlight.static_probe=true` 时，走**静止补检**。

**B2. 补检怎么做（成本已压到最低）**
- 从**已抽好的粗扫帧**中等间隔取 K 帧（`static_probe_frames`，默认 2），
  用**粗扫检测器 + CLAHE**（640 / `coarse_conf` 0.15）跑 K 次推理。
- 为什么用 640 而不是 1280：本步要回答的是"**预筛跳过是否漏掉了目标**"，
  与粗扫同分辨率同阈值才可比；"1280 是否更准"是 Track A 的问题，别混进来。
  代价：每视频 ≈ 0.2s 推理（复用已有帧，**零额外抽帧**）。
- 命中 person ⇒ 生成一个 **C 级静帧事件**（`motion_only=False, level=LV_SUSPECT`），
  只留一张代表帧（物证），**不判"无精华"**；`stats['static_probe'] = "hit"`。
- 未命中 ⇒ `stats['static_probe'] = "no_hit"`，正常写"无精华"（此时是**真的复核过**）。
- 新配置：`highlight.static_probe`(true) / `static_probe_frames`(2) / `static_probe_conf`(沿用 coarse_conf)。
- 幂等：`videos.highlight_probe_at TEXT` 时间戳；补检只处理
  `highlight_clips='[]' AND COALESCE(highlight_sent,0)=0 AND highlight_probe_at IS NULL`。

**B3. 先试点再全量**
- 先跑 100 条测**捞回率**（命中 person 的比例）。
- 判据（沿用 Phase 2.5 的既有习惯）：捞回率 ≥1% ⇒ 全量开启并写进默认配置；
  <1% ⇒ 保留开关默认关，但**仍要把"预筛跳过"这个语义在 UI 上讲清楚**（由 Track 0 承担）。
- 全量：2,832 条 × ≈0.6s ≈ **30 分钟**（含抽帧 I/O，纯推理仅 ≤10 分钟）。

## 8. 成本与收益

**成本（仅 YOLO 检测耗时，实测单价 640=97ms / 960=211ms / 1280=361ms）**

## 9. 风险与回滚

| 风险 | 影响 | 对策 |
|---|---|---|
| **抬精度导致真人漏检** | 真人素材被放行（可撤销，但违背"宁可多留"红线） | ① 主手段用**多帧一致性**而非抬阈值；② 校准报告硬指标"漏检增量 = 0"；③ 放行只到回收目录、可撤销；④ 配置一键退回 |
| 补检把误报当物证，C 级静帧虚增 | 复查负担上升 | 补检阈值沿用 `coarse_conf`；若试点发现 C 级虚增，只提高阈值不改结构 |
| 原片已被用户手动删除 | 补检/重跑无法执行 | 执行前探测存在性，缺失则跳过并计数如实报告（照 `archiver` 的"缓存缺失跳过"做法） |
| 改 stats/字段影响 ADR 0004 一键链路 | 流程回归 | 补检作为 **highlight 阶段内部**分支，**不新增阶段**，六阶段契约不变 |
| 历史行阈值不一致（现存 `has_person=1 / person_conf=0.3`，与当前 0.4 不符） | 统计口径混乱 | 由 `analysis_version` 标记；P4 后可统一重跑，未重跑的行在报告里注明 |
| 校准样本量不足导致结论不稳 | 定错参数 | 分层抽样固定种子；报告必须给出每组的 n 与置信区间说明 |

**回滚**：所有行为改变均由配置键控制（`clahe` / `person_min_frames` / `static_probe`），
退回默认值即回到当前行为；代码层无迁移破坏（只增列，不改列）。

## 10. 待拍板的决策点（拍板后落 ADR 0006）

**Q1（Track B 的前提）**：「整片静止」是否等于「无人」？
- 方案 A（本计划假设）：**不等于**，补检 K 帧；检出就留 C 静帧，不判无精华。
- 方案 B：承认这条捷径，**不动代码**，只做 Track 0 把"预筛跳过"的数字讲清楚。

**Q2（Track A 的路线）**：L1 提精度用哪条？
- 方案 A（推荐）：**多帧一致性**（`person_min_frames`），额外算力 ≈0。
- 方案 B：**只抬阈值**（0.4 → 0.5+）—— 简单，但会把低分真人一起干掉，风险更高。
- 方案 C：CLAHE + 多帧一致性 + 抬阈值（全都要，由校准报告定组合）。

**Q3（Track A 的生效范围）**：口径改完后，是否对已处理的 4,825 条**全量重跑 L1**？
- 重跑会把历史 `has_person` 刷新，可能改变"处置候选"集合（有整理价值，也有扰动）。
- 建议：先只对**已搬入回收 + L1 报有人**的 162 条重跑（成本分钟级），观察后再决定全量。

**Q4**：Track B 捞回率若 < 1%，是全量开启并写进默认，还是保持开关默认关闭？
